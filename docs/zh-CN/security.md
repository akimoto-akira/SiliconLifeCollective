# 安全设计

> **版本：v0.2.0-alpha**

[English](../en/security.md) | [Deutsch](../de-DE/security.md) | **中文** | [繁體中文](../zh-HK/security.md) | [Español](../es-ES/security.md) | [日本語](../ja-JP/security.md) | [한국어](../ko-KR/security.md) | [Čeština](../cs-CZ/security.md) | [Русский](../ru-RU/security.md)

## 概述

Silicon Life Collective 的安全性建立在**分层防御**模型之上。核心原则：**所有 I/O 操作必须通过执行器**，执行器在执行前强制执行权限检查。

```
工具调用 → 执行器 → 权限管理器 → 频率缓存 → 回调 → (IsCurator: 询问用户 | Non-curator: 全局ACL)
```

---

## 权限模型

### 权限类型

| 类型 | 描述 |
|------|-------------|
| `NetworkAccess` | 出站 HTTP/HTTPS 请求 |
| `CommandLine` | Shell 命令执行 |
| `FileAccess` | 文件和目录操作 |
| `Function` | 敏感函数调用 |
| `DataAccess` | 访问系统或用户数据 |

### 权限结果

每次权限检查返回三种结果之一：

| 结果 | 行为 |
|--------|----------|
| **Allowed（允许）** | 操作立即进行 |
| **Denied（拒绝）** | 操作被阻止，记录审计日志 |
| **AskUser（询问用户）** | 操作暂停，需要用户确认 |

### 特殊角色：硅基主理人

硅基主理人拥有最高权限级别（`IsCurator = true`）。当权限链到达分支判断时，主理人的操作会通过 `IPermissionAskHandler` 询问用户确认，而非直接短路为允许。非主理人则查询全局 ACL。

### 私有权限管理器

每个硅基生命体都有自己的**私有 PermissionManager** 实例。权限状态不在生命体之间共享。

## 权限验证流程

查询优先级为：**1. 频率缓存 → 2. 回调函数 → 3. 分支判断（IsCurator/GlobalACL）**

```
┌─────────────┐
│ 工具调用     │
└──────┬──────┘
       │
       ▼
┌─────────────┐     ┌─────────────────────┐
│  执行器      │────▶│ 私有权限            │
│（磁盘/网络/  │     │ 管理器（每个生命体）  │
│  命令行...） │     └────────┬────────────┘
└─────────────┘            │
                           ▼
                  ┌─────────────────┐
                  │ 1. 频率缓存      │──匹配──▶ 允许 / 拒绝
                  │（高拒绝优先于    │
                  │   高允许）       │
                  └────────┬────────┘
                           │ 未匹配
                           ▼
                  ┌─────────────────┐
                  │ 2. 权限         │
                  │  回调函数        │──▶ 允许 / 拒绝 / 询问用户
                  └────────┬────────┘
                           │ 询问用户
                           ▼
                  ┌─────────────────┐
                  │ 3. IsCurator?   │
                  └────────┬────────┘
                           │
                 ┌─────────┴─────────┐
                 │                   │
                 ▼ 是                ▼ 否
          ┌─────────────┐    ┌─────────────┐
          │ 询问用户     │    │ 全局 ACL     │
          │（AskHandler）│    │ 查询规则     │
          └─────────────┘    └─────────────┘
```

**关键点**：执行器只看到布尔值（允许/拒绝）。权限管理器内部处理三元决策（允许/拒绝/询问用户），并在返回给执行器之前解决询问用户。

## 执行器（安全边界）

执行器是 I/O 操作的**唯一**路径。它们强制执行：

### 独立调度线程

每个执行器拥有**独立的调度线程**：

- 执行器之间的线程隔离 —— 一个执行器的线程阻塞不影响其他执行器。
- 每个执行器可以设置独立的资源限制（CPU、内存等）。
- 执行器线程的线程池管理。

### 请求队列

每个执行器维护一个请求队列：

- 请求按类型路由到相应的执行器。
- 支持优先级排队。
- 每个请求的超时控制。

### 权限验证的线程锁定

当工具发起资源访问时：

1. 执行器接收请求并**锁定其线程**。
2. 执行器查询生命体的私有权限管理器。
3. 如果回调返回询问用户，执行器线程**保持锁定**等待用户响应。
4. 生命体只看到最终结果（成功或拒绝） —— 它永远不会看到中间的"待处理"或"等待"状态。
5. 只有硅基主理人会触发真正的用户提示。普通生命体同步查询全局 ACL 而不阻塞。
6. 超时时，请求被视为拒绝，线程锁被释放。

### 执行器类型

| 执行器 | 范围 | 默认超时 |
|----------|-------|-----------------|
| `DiskExecutor` | 文件读/写、目录操作 | 30 秒 |
| `NetworkExecutor` | HTTP 请求、WebSocket 连接 | 60 秒 |
| `CommandLineExecutor` | Shell 命令执行 | 120 秒 |

> **注意**：`DynamicCompilationExecutor`（位于 `SiliconLife.Core.Compilation` 命名空间）负责 Roslyn 内存编译，不属于 I/O 执行器范畴，但同样受权限系统约束。

### 异常隔离与容错

- 一个执行器的异常不影响其他执行器。
- 线程崩溃时自动重启。
- 熔断器：连续失败后暂时停止执行器以防止级联失败。

## 全局 ACL（访问控制列表）

共享规则表持久化到存储，仅由硅基主理人管理：

```json
{
  "rules": [
    { "prefix": "network:api.github.com", "result": "Allowed" },
    { "prefix": "file:C:\\Windows", "result": "Denied" },
    { "prefix": "cli:rm -rf", "result": "Denied" }
  ]
}
```

- 规则按顺序评估；第一次匹配获胜。
- 只有硅基主理人可以修改全局 ACL（通过其专用工具）。
- 更改立即生效。
- 全局 ACL **不在**上述每个查询的优先级链中 —— 它在内部由回调函数引用。

## 用户频率缓存

为减少重复的权限提示，系统维护两个**每个生命体、仅内存**的缓存：

| 缓存 | 用途 |
|-------|---------|
| **HighAllow（高允许）** | 用户频繁允许的资源 |
| **HighDeny（高拒绝）** | 用户频繁拒绝的资源 |

### 工作原理

- **用户选择，非自动检测**：当触发询问用户时，用户选择是否将资源添加到缓存。
- **前缀匹配**：支持资源路径前缀匹配（例如 `network:api.example.com/*`）。
- **优先级**：高拒绝的优先级高于高允许。
- **仅内存**：缓存不持久化。重启时丢失。
- **可配置过期**：用户可以设置缓存条目的有效期限。

### 缓存更新流程

1. 权限回调返回 `AskUser`。
2. 权限系统向卡片系统（Web UI 或即时通讯）发送查询。
3. 用户做出决策（允许/拒绝）并**选择是否缓存**。
4. 卡片系统返回决策 + 缓存标志。
5. 权限系统更新相应的缓存列表。
6. 未来匹配缓存前缀的请求立即解决。

## 用户询问机制

当权限检查返回 `AskUser` 时：

### Web UI：交互式卡片

Web 前端立即显示**交互式卡片**，显示：

- 资源类型和路径
- 操作描述
- 允许 / 拒绝按钮
- 可选的"始终允许" / "始终拒绝"复选框（添加到频率缓存）

### 即时通讯（无卡片支持）：随机码

对于不支持交互式卡片的消息传递平台：

1. 系统生成两个随机 6 位代码：**允许代码**和**拒绝代码**。
2. 发送包含资源信息和两个代码的消息。
3. 用户必须回复准确的允许代码才能授权。任何其他回复被视为拒绝。
4. 代码是单次使用的，以防止重放攻击。

### 超时

- 为所有询问用户请求设置超时。
- 超时时，请求被视为**拒绝**，执行器线程锁被释放。

## 动态编译安全

自我进化（类重写）引入了独特的安全风险。系统使用**分层策略**缓解它们：

### 第 1 层：编译时引用控制（主要防御）

- 编译器只获得**允许的装配引用列表**。
- **允许**：`System.Runtime`、`System.Private.CoreLib`、项目装配（ITool 接口等）
- **阻止**：`System.IO`、`System.Reflection`、`System.Runtime.InteropServices` 等
- 如果代码引用了被阻止的装配，**编译器本身拒绝**代码。
- 这比运行时扫描更可靠 —— 危险操作在类型级别是不可能的。

### 第 2 层：运行时静态分析（次要防御）

- 即使成功编译后，代码也要进行静态模式扫描。
- 检测危险操作模式（直接 I/O、系统调用等）。
- 如果发现危险代码，加载被拒绝，系统回退到默认功能。

### 继承约束

所有自定义硅基生命体类**必须**继承 `SiliconBeingBase`。编译器在类型级别强制执行此约束。

### 加密存储

编译的代码在磁盘上以 AES-256 加密存储：

- **密钥派生**：从生命体的 GUID（大写）使用 PBKDF2。
- **解密失败**：回退到默认实现。
- **运行时重新编译**：新代码先在内存中编译；只有在成功编译和实例替换后才持久化。

### 原子替换

替换过程是原子的：

1. 在内存中编译新代码 → 获取 `Type`。
2. 从 `Type` 创建新实例。
3. 从旧实例迁移状态到新实例。
4. 交换引用。
5. 持久化加密代码。

如果任何步骤失败，旧实例保持活动。

## 权限回调函数

### 设计

每个 PermissionManager 持有**回调函数变量**：

- **默认**：指向内置默认权限函数。
- **动态编译后**：被生命体的自定义权限函数覆盖。
- **二选一**：任何时候只有一个回调处于活动状态。
- **编译失败**：不影响当前回调 —— 默认或上次成功的自定义函数保持有效。

### 回调签名

```
PermissionResult Callback(PermissionType type, string resourcePath, Guid callerId)
```

返回 `Allowed`、`Denied` 或 `AskUser`。

## Token 使用审计

`TokenUsageAuditManager` 提供与安全性相关的 AI token 消耗跟踪：

- **每次请求记录** —— 每次 AI 调用记录生命体 ID、模型、提示词 token、补全 token 和时间戳。
- **异常检测** —— 异常的 token 消耗模式可能表明提示词注入或资源滥用。
- **仅主理人访问** —— `TokenAuditTool`（标记为 `[SiliconManagerOnly]`）允许主理人查询和汇总 token 使用。
- **Web 仪表板** —— `UsageController` 提供基于浏览器的仪表板，带趋势图和数据导出。
- **持久化存储** —— 记录通过 `ITimeStorage` 存储，用于时间序列查询和长期分析。

## 插件安全

插件系统引入了第三方代码执行的安全风险，通过以下机制缓解：

### 安全沙箱与能力声明

`PluginLoader` 在加载插件时执行安全扫描，同时支持能力声明机制：

1. **可声明能力** — 插件通过 `[PluginCapability]` 属性声明所需能力：
   - `Network` — 网络访问（允许引用 `System.Net.Http`、`System.Net.WebSockets`、`System.Net.Sockets`）
   - `FileIO` — 文件读写（允许引用 `System.IO`）
   - `Process` — 进程管理
   - `AI` — AI 调用

2. **不可声明能力** — 以下能力始终被阻止：
   - P/Invoke（`System.Runtime.InteropServices`）
   - Unsafe 代码（`System.Runtime.CompilerServices.Unsafe`）
   - 反射发射（`System.Reflection.Emit`）
   - 编译器 API（`Microsoft.CodeAnalysis`）

3. **可信程序集白名单** — 以下程序集的引用被允许：
   - `Google.Protobuf`、`Newtonsoft.Json`、`MessagePack`
   - `Serilog`、`Microsoft.Extensions.Logging.Abstractions`
   - `Dapper`

4. **禁止类型检查** — 扫描插件中引用的危险类型

5. **禁止成员检查** — 扫描插件中调用的危险方法

### 隔离加载

- 使用自定义 `AssemblyLoadContext` 隔离加载每个插件
- 插件之间的类型和程序集不会互相干扰
- 插件卸载时可以释放相关资源

### 工具权限约束

- 插件通过 `ITool` 接口注册的工具受相同的权限系统约束
- 插件工具不能绕过权限验证链
- 插件工具受 `[SiliconManagerOnly]` 标记约束

## 工具权限安全

工具权限系统提供了额外的安全层，控制硅基生命体可以使用哪些工具操作：

### 两级权限隔离

1. **硅基生命体级别** — 每个硅基生命体有独立的工具权限配置
2. **项目级别** — 项目空间内的工具权限独立于硅基生命体级别，实现项目间的权限隔离

### 权限模板

系统提供预定义的权限模板，确保安全基线：

- **readonly** — 最小权限，仅允许读取操作
- **restricted** — 受限权限，仅允许基本操作
- **full** — 完整权限（仅主理人使用）

### 安全特性

- **默认拒绝** — 未明确允许的工具操作默认被拒绝
- **操作粒度** — 每个工具的每个操作独立控制（如 `network:get` 允许但 `network:post` 拒绝）
- **主理人管理** — 工具权限只能由硅基主理人配置
- **审计追踪** — 工具权限变更记录在审计日志中

## 技能安全

技能系统复用工具权限体系，并提供多层护栏：

### 执行权限

- 技能 id 作为工具名，以 `execute` 动作纳入 `ToolActionPermissionConfig` 权限矩阵
- 被禁用的技能不会出现在 AI 可见的工具定义中（Schema 层过滤 + 运行时复核双重保障）
- 主理人始终可执行；普通生命体需 `IsActionAllowed(skillId, "execute")`

### 工具白名单与权限并集

- 技能执行期间仅允许 `ToolWhitelist` 内的工具（空列表 = 继承生命体全部工具）
- 技能的动作限制与生命体权限**取严格侧并集**（`MergePermissions`）：技能只能进一步收窄权限，永远不能放权
- 白名单外的工具调用直接失败（`Tool not in whitelist`）

### 资源消耗护栏

- **全局开关**：`SkillEnabled` 一键禁用整个技能系统
- **数量配额**：每个生命体自定义技能数受 `MaxCustomSkillsPerBeing`（默认 50）限制
- **轮数钳制**：`maxToolRound = Min(技能声明值, GlobalMaxToolRound 默认 10)`，防止失控循环
- **超时钳制**：`timeout = Min(技能声明值, GlobalSkillTimeoutSeconds 默认 300s)`
- **递归防护**：技能执行中不能再调用自身

### 修改权限

- 主理人可修改所有技能；普通生命体仅能修改来源为 `Being`/`User` 的技能
- 元数据自动补全只填充缺失字段，用户提供的字段永不被 AI 覆盖

## MCP 安全

MCP 集成遵循"用户主权 + 权限一致"原则：

### 用户主权

- MCP 服务器的添加、删除、启停、重连**只能由用户通过 Web UI**（/mcp 或配置页）完成
- AI 侧的 `mcp` 工具是只读查询（status/list_servers/list_tools），无法修改服务器列表
- `McpEnabled` 全局开关可一键切断所有外部工具

### 工具隔离与权限

- 包装工具以 `mcp_{serverId}_{toolName}` 命名，与内置/插件工具命名空间隔离
- 每个包装工具自动声明单一 `execute` 动作，纳入两级工具权限矩阵，可按生命体/项目逐个禁用
- 禁用服务器后其工具立即从所有生命体注销

### 传输与进程边界

- `stdio` 服务器以子进程运行，仅继承显式配置的环境变量（`env` 字段）
- `http` 服务器通过配置的端点通信，连接失败自动进入 error 状态并暴露 `lastError`

## IM 密钥安全

### 环境变量占位符

IM 平台配置值支持 `${ENV_VAR}` 占位符（如 `"${FEISHU_APP_SECRET}"`）：

- `ConfigSecretResolver` 在**深拷贝副本**上解析占位符，原始 `config.json` 始终保持占位符原样
- 后续 `SaveConfig` 不会把解析后的明文密钥写回磁盘
- 支持整值占位符与值内嵌占位符（如 `prefix-${VAR}`）

### OAuth 授权安全

- **state 防 CSRF**：16 字节加密随机数，回调时严格校验
- **5 分钟超时**：授权会话超时自动作废，旧会话被覆盖时立即取消
- **令牌存储**：accessToken/refreshToken/tokenExpiresAt 写回平台配置并持久化，`authMode` 标记为 `oauth`
- 回调 URL 支持 `redirectBaseUrl` 配置（公网回调场景）

### 消息安全

- 飞书：签名验证（`X-Lark-Signature`，SHA256）+ AES-256-CBC 事件解密 + 事件去重（10 分钟窗口）
- 企业微信：WXBizMsgCrypt 加解密与签名验证
- 钉钉：Stream 模式走加密 WebSocket；HTTP 模式回调校验
