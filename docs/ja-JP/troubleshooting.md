## 一般的な問題

### ビルドとコンパイル

#### 問題：依存関係の欠落でビルド失敗

**症状**：
```
error CS0246: The type or namespace name 'Microsoft.CodeAnalysis' could not be found
```

**解決策**：
```bash
dotnet restore
dotnet build
```

#### 問題：.NET SDK が見つからない

**症状**：
```
The .NET SDK could not be found
```

**解決策**：
1. .NET 9 SDK をインストール：https://dotnet.microsoft.com/download/dotnet/9.0
2. インストールを検証：
```bash
dotnet --version
```

### AI 接続問題

#### 問題：Ollama 接続拒否

**症状**：
```
Failed to connect to Ollama at http://localhost:11434
```

**解決策**：
```bash
# Ollama が実行中か確認
ollama list

# Ollama を起動
ollama serve

# 接続をテスト
curl http://localhost:11434/api/tags
```

#### 問題：モデルが見つからない

**症状**：
```
model "qwen2.5:7b" not found
```

**解決策**：
```bash
# 必要なモデルをプル
ollama pull qwen2.5:7b

# 利用可能なモデルをリスト
ollama list
```

#### 問題：百錬 404 エラー

**症状**：
```
HTTP 404: Model not found
```

**解決策**：
1. API キーが正しいことを確認
2. モデル名が百錬カタログと一致するか確認
3. リージョンエンドポイントが正しいことを確認
4. アカウントがモデルにアクセスできるか確認

#### 問題：Volcengine Ark 接続失敗

**症状**：
```
HTTP 401: Unauthorized
または
HTTP 404: Endpoint not found
```

**解決策**：
1. API キーが正しいことを確認
2. Endpoint URL の形式が正しいことを確認（デフォルト：`https://ark.cn-beijing.volces.com/api/v3/chat/completions`）
3. Model パラメータにモデル名ではなく推論エンドポイント ID（例：`ep-20241212123456-abcde`）を使用しているか確認
4. アカウントがエンドポイントにアクセスできるか確認

### 実行時問題

#### 問題：ポートが既に使用されている

**症状**：
```
HttpListenerException: Address already in use
```

**解決策**：

**Windows**：
```bash
netstat -ano | findstr :8080
taskkill /PID <PID> /F
```

**Linux/Mac**：
```bash
lsof -ti:8080 | xargs kill -9
```

**または設定でポートを変更**。

#### 問題：シリコンビーイングが起動しない

**症状**：
- シリコンビーイングの状態が「Error」を表示
- ログに初期化失敗が表示

**解決策**：
1. ソウルファイルが存在し、有効か確認
2. AI クライアントが設定されていることを確認
3. ログで具体的なエラーを確認：
```bash
tail -f logs/*.log
```

#### 問題：メモリ不足

**症状**：
```
OutOfMemoryException
```

**解決策**：
1. **SiliconLife.Default**：ヒープサイズを増加：
```bash
dotnet run --project src/SiliconLife.Default --server.gcHeapCount 4
```

2. **SiliconLife.Fast**：Fast バージョン自体のメモリ使用量が高い（~500MB）。メモリが継続的に不足する場合は、以下を推奨：
   - 同時実行シリコンビーイング数を削減
   - 古いデータをクリーンアップしてメモリを解放

3. 古いデータをクリーンアップ：
```bash
# 古いログをアーカイブ
mv logs/ logs-archive/
mkdir logs

# 古いメモリをクリーンアップ
# Web UI 経由：メモリ管理 > クリーンアップ
```

> **ヒント**：SiliconLife.Default のメモリ使用量は低い（~200MB）ため、メモリ制限のある環境に適しています。SiliconLife.Fast はメモリ使用量が高いですがパフォーマンスが優れており、本番環境に適しています。

### 権限問題

#### 問題：権限が拒否された

**症状**：
```
Permission denied: FileAccess C:\Windows
```

**解決策**：
1. 現在の権限を確認：
```bash
curl http://localhost:8080/api/permissions/list
```

2. 権限を付与：
```bash
curl -X POST http://localhost:8080/api/permissions/save \
  -H "Content-Type: application/json" \
  -d '{
    "permissionType": "FileAccess",
    "resourcePrefix": "C:\\Projects",
    "result": "Allowed",
    "description": "Allow project directory access"
  }'
```

3. または Web UI を使用：権限管理

#### 問題：権限が期限切れにならない

**症状**：
- 権限が有効期限後もまだ有効

**解決策**：
1. システムクロックの同期を確認
2. `expiresAt` フィールドが正しく設定されていることを確認
3. 権限キャッシュをクリア

### Web UI 問題

#### 問題：Web UI にアクセスできない

**症状**：
- ブラウザに「Connection refused」と表示

**解決策**：
1. サーバーが実行中であることを確認
2. 正しい URL を確認：`http://localhost:8080`
3. ファイアウォール設定を確認
4. ログで起動エラーを確認

#### 問題：SSE が機能しない

**症状**：
- リアルタイム更新が表示されない
- チャットがストリーミングされない

**解決策**：
1. ブラウザが SSE をサポートしていることを確認
2. SSE のプロキシバッファリングを無効化
3. ネットワークの安定性を確認
4. 別のブラウザを試す

#### 問題：UI が壊れて見える

**症状**：
- スタイルが正しくない
- レイアウトが崩れている

**解決策**：
1. ブラウザのキャッシュをクリア
2. 別のスキンを試す：設定 > スキン
3. ブラウザのコンソールでエラーを確認
4. ブラウザの拡張機能を無効化

### ストレージ問題

#### 問題：データの読み取り/書き込みができない

**症状**：
```
IOException: Access denied
```

**解決策**：
1. ファイル権限を確認
2. ストレージパスが存在することを確認
3. ディスク容量を確認
4. 適切な権限で実行

#### 問題：データ破損

**症状**：
- JSON パースエラー
- データの欠落

**解決策**：
1. バックアップから復元
2. ストレージの整合性を確認：
```bash
# Web UI 経由：システム > ストレージチェック
```

3. 破損したファイルを手動で修復

#### 問題：SpeedyPack ストレージファイルの破損（Fast 版）

**症状**：
- `.spk` ファイルが読み込めない
- SpeedyStorage の初期化に失敗

**解決策**：
1. `SiliconLife.Speedy.Manager` ツールを使用して `.spk` ファイルをチェックおよび修復
2. `.spk.idx` インデックスファイルが `.spk` ファイルと一致するか確認
3. インデックスファイルが破損している場合、`.spk.idx` ファイルを削除。システムが自動的にインデックスを再構築
4. バックアップから `.spk` ファイルを復元

#### 問題：SpeedyPack 自動圧縮の失敗（Fast 版）

**症状**：
- `.spk` ファイルが継続的に増大
- ディスク容量不足

**解決策**：
1. `SpeedyPackAutoCompactor` が正常に動作しているか確認
2. 手動で圧縮操作をトリガー
3. 圧縮閾値の設定を確認
4. `SiliconLife.Speedy.Manager` ツールで手動圧縮

### プラグイン問題

#### 問題：プラグインの読み込みに失敗

**症状**：
```
Plugin load failed: Security check failed
```

**解決策**：
1. プラグインが宣言不可能な禁止名前空間を参照していないか確認（例：`System.Runtime.InteropServices`、`System.Reflection.Emit`、`Microsoft.CodeAnalysis`）
2. プラグインが `System.IO` や `System.Net.Http` を必要とする場合、`[PluginCapability]` で `FileIO` や `Network` 能力を宣言しているか確認
3. プラグインが信頼できるアセンブリホワイトリスト内のアセンブリのみを参照していることを確認
4. プラグインが `IPlugin` インターフェースを正しく実装していることを確認
5. ログでセキュリティチェック失敗の詳細を確認

#### 問題：プラグインツールが登録されない

**症状**：
- プラグインの読み込みは成功したが、ツールがツールリストに表示されない

**解決策**：
1. プラグイン内のツールクラスが `ITool` インターフェースを正しく実装していることを確認
2. ツールクラスが public であることを確認
3. `ToolManager.ScanAllPluginAssemblies()` が呼び出されていることを確認
4. プラグインを再ビルドしてアプリケーションを再起動

### ワークノート問題

#### 問題：ワークノートを作成できない

**症状**：
```
Failed to create work note
```

**解決策**：
1. シリコンビーイングが存在し実行状態であることを確認
2. ストレージパスに書き込み権限があることを確認
3. コンテンツが空でないことを確認（コンテンツは必須）
4. ログで詳細なエラー情報を確認

#### 問題：ノート検索で結果が返らない

**症状**：
- キーワード検索が空の結果を返す
- 関連するノートが確実にある

**解決策**：
1. キーワードのスペルが正しいことを確認
2. より一般的なキーワードを試す
3. ノートにそのキーワードが含まれていることを確認（大文字小文字を区別）
4. `max_results` パラメータの値を増加

#### 問題：ノート目次の生成が遅い

**症状**：
- 目次生成時の応答時間が長い
- シリコンビーイングに大量のノートがある（>1000 ページ）

**解決策**：
1. これは正常な動作。すべてのノートを走査する必要がある
2. 古いノートの定期的なアーカイブを検討
3. 目次ブラウズの代わりに検索機能を使用
4. 計画中の最適化：目次キャッシュメカニズムの追加

### ナレッジネットワーク問題

#### 問題：ナレッジクエリが空の結果を返す

**症状**：
```
No knowledge triples found
```

**解決策**：
1. 主語と述語のスペルを確認
2. ナレッジがネットワークに追加されていることを確認
3. 検索機能でファジーマッチングを使用：
```json
{
  "action": "search",
  "query": "キーワード"
}
```

#### 問題：ナレッジパスの検索に失敗

**症状**：
```
No path found between concepts
```

**解決策**：
1. 2つの概念がナレッジネットワークに存在することを確認
2. 関連パスが存在するか確認（直接的または間接的な関係がない可能性）
3. 接続を確立するためにナレッジを追加
4. パス長制限を下げる（設定されている場合）

#### 問題：ナレッジ検証に失敗

**症状**：
```
Knowledge validation failed
```

**解決策**：
1. 三つ組の形式が正しいことを確認（主語、述語、目的語は必須）
2. 信頼度が 0.0-1.0 の範囲内であることを確認
3. 重複する三つ組がないか確認
4. 検証エラーの詳細を確認して具体的な問題を把握

#### 問題：ナレッジネットワーク統計情報が不正確

**症状**：
- 統計数値が予想と一致しない
- ナレッジ追加後に統計が更新されない

**解決策**：
1. 統計情報の更新に数秒かかる場合がある（キャッシュ）
2. 削除操作が正常に実行されなかったか確認
3. アプリケーションを再起動して統計を強制更新
4. API で統計情報を再クエリ

### プロジェクト管理問題

#### 問題：プロジェクトを作成できない

**症状**：
```
Failed to create project
```

**解決策**：
1. プロジェクト名が空でないことを確認（必須）

#### 問題：プロジェクトデータの消失

**症状**：
- プロジェクト情報が読み込めない
- プロジェクトファイルが破損

**解決策**：
1. プロジェクトストレージディレクトリが存在するか確認
2. バックアップからプロジェクトデータを復元
3. JSON ファイルの形式が正しいことを確認
4. 破損したプロジェクトファイルを手動で修復

#### 問題：プロジェクトロールの割り当てに失敗

**症状**：
```
Failed to assign role
```

**解決策**：
1. シリコンビーイングがプロジェクトに参加していることを確認
2. ロール名が有効であることを確認
3. 操作者がシリコンキュレーターであることを確認
4. ログで詳細なエラー情報を確認

#### 問題：ワークフローを開始できない

**症状**：
- ワークフローインスタンスの作成に失敗
- 状態遷移が実行されない

**解決策**：
1. ワークフローテンプレートが定義されていることを確認
2. 初期状態が正しく設定されていることを確認
3. プロジェクトにワークフローテンプレートがバインドされていることを確認
4. ワークフローログで遷移エラーを確認

### ツール権限問題

#### 問題：ツール操作が拒否された

**症状**：
```
Tool operation denied: network:post
```

**解決策**：
1. シリコンビーイングのツール権限設定を確認：
```bash
curl http://localhost:8080/api/beings/tool-permissions?beingId=<id>
```

2. ツール権限を更新：
```bash
curl -X PUT http://localhost:8080/api/beings/tool-permissions \
  -H "Content-Type: application/json" \
  -d '{
    "beingId": "being-uuid",
    "permissions": {
      "network:post": "allowed"
    }
  }'
```

3. または Web UI を使用：シリコンビーイング → ツール権限

#### 問題：プロジェクトツール権限が反映されない

**症状**：
- プロジェクトレベルのツール権限が期待通りに動作しない

**解決策**：
1. プロジェクトレベルの権限が正しく設定されていることを確認
2. シリコンビーイングレベルとプロジェクトレベルの権限が競合していないか確認
3. プロジェクトレベルの権限はシリコンビーイングレベルとは独立しており、両者の積集合が適用される
4. 監査ログで権限チェック結果を確認

## デバッグ

### 詳細ログの有効化

設定を編集：
```json
{
  "logging": {
    "level": "debug"
  }
}
```

### ログの確認

ログの保存先：
```
logs/
├── system.log
├── ai.log
├── permission.log
└── error.log
```

リアルタイム表示：
```bash
tail -f logs/*.log
```

### デバッガーの使用

**SiliconLife.Default（デフォルト実装）**：
```bash
# デバッガーで実行
dotnet run --project src/SiliconLife.Default --configuration Debug

# デバッガーをアタッチ
# IDE 経由：プロセスにアタッチ > SiliconLife.Default
```

**SiliconLife.Fast（高性能バージョン）**：
```bash
# デバッガーで実行
dotnet run --project src/SiliconLife.Fast --configuration Debug

# デバッガーをアタッチ
# IDE 経由：プロセスにアタッチ > SiliconLife.Fast
```

> **推奨**：開発デバッグ段階では SiliconLife.Default の使用を推奨。アーキテクチャ検証完了後に SiliconLife.Fast を本番デプロイに使用。

## パフォーマンス問題

### 応答時間が遅い

**最適化**：
1. AI モデルの複雑さを下げる
2. キャッシュを有効化
3. 古いデータをクリーンアップ
4. システムリソースを増加

### CPU 使用率が高い

**確認**：
- 多すぎるシリコンビーイングが実行中
- ツール内の無限ループ
- 頻繁なタイマー実行

**解決策**：
- 並行シリコンビーイングを削減
- ツールコードを最適化
- タイマー間隔を調整

### メモリ使用率が高い

**モニタリング**：
```bash
# Web UI 経由：ダッシュボード > メモリ
```

**最適化**：
- 古いメモリをクリーンアップ
- コンテキストサイズを削減
- ページネーションを実装

## 緊急手順

### システムクラッシュ

1. ログで原因を確認
2. アプリケーションを再起動：

**SiliconLife.Default（デフォルト実装）**：
```bash
dotnet run --project src/SiliconLife.Default
```

**SiliconLife.Fast（主力本番バージョン）**：
```bash
dotnet run --project src/SiliconLife.Fast
```

3. 必要に応じてバックアップから復元

### データ消失

1. 直ちにアプリケーションを停止
2. バックアップファイルを確認
3. データを復元
4. 整合性を検証

### セキュリティ脆弱性

1. すべてのシリコンビーイングを停止
2. すべての権限を取り消し
3. 監査ログを確認
4. アクセス制御を確認
5. 制限権限で再起動
