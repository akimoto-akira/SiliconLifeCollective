## デュアルバージョンロードマップ

### SiliconLife.Default（デフォルトバージョン）
- **位置づけ**：デフォルト実装、主にアーキテクチャの実現可能性を検証するために使用
- **現在の状態**：フェーズ 1～10.6 が完了、システムは安定稼働中
- **役割の説明**：アーキテクチャ検証のベースライン実装として、コアアーキテクチャ設計の正確性と実現可能性を確保

### SiliconLife.Fast（高性能バージョン）
- **位置づけ**：本番推奨バージョン
- **現在の状態**：基礎アーキテクチャの移植完了、SpeedyPackストレージエンジンとプラグインシステムを実装済み
- **役割の説明**：Defaultバージョンで検証されたアーキテクチャを基に、深いパフォーマンス最適化と本番級機能強化を行い、実際のデプロイにおける第一選択

**Fastバージョン開発計画**：
- ✅ フェーズ 1：基礎プロジェクト構造と設定システムの移植
- ✅ フェーズ 2：Web UI とコントローラーの移植
- ✅ フェーズ 3：ストレージシステム最適化（SpeedyPackメモリストレージ + 非同期永続化）
- ✅ フェーズ 3.5：SpeedyPackマネージャー（SiliconLife.Speedy.Manager Avalonia UI アプリケーション）
- ✅ フェーズ 3.6：プラグインシステム（IPluginインターフェース、セキュリティサンドボックス、AssemblyLoadContext隔離）
- ✅ フェーズ 4：Avaloniaウィンドウアプリケーション（クロスプラットフォームデスクトップアプリ、Windows/macOSシステムトレイ、Linuxステータスウィンドウ）

## ガイド原則

各フェーズは**実行可能で観察可能**なシステムで終了する。どのフェーズも「インフラだけあって見せるものがない」状態にはならない。

## ~~フェーズ 6：ルールの遵守（パーミッションシステム）~~ ✅ 完了

**目標**：シリコンビーイングが未承認で機密リソースにアクセスできない。

| # | モジュール | 説明 |
|---|--------|-------------|
| 6.1 | パーミッションマネージャー | 各ビーイングのプライベートインスタンス。コールバックベース、三値結果（Allowed/Deny/AskUser）。クエリ優先度：HighDeny → HighAllow → Callback。IsCuratorフラグ |
| 6.2 | パーミッションタイプ列挙型 | NetworkAccess、CommandLine、FileAccess、Function、DataAccess |
| 6.3 | DefaultPermissionCallback | ネットワークホワイトリスト/ブラックリスト、CLI分類、ファイルパスセキュリティルール |
| 6.4 | グローバルACL | プレフィクスマッチングルールテーブル、ストレージに永続化 |
| 6.5 | ユーザー高頻度キャッシュ | HighAllow/HighDenyリスト。ユーザー選択（自動検出ではない）。プレフィクスマッチング、メモリのみ、設定可能な有効期限 |
| 6.6 | ユーザー問合せメカニズム（コンソール） | AskUserが返された時、コンソールでy/nをプロンプト |
| 6.7 | エグゼキューターパーミッション統合 | すべてのエグゼキューターが実行前にパーミッションをチェック |
| 6.8 | IStorage隔離の説明 | IStorageはシステム内部の永続化 —— 直接ファイルアクセス、エグゼキューターを経由**しない**、AIが制御**不可**。エグゼキューターはAIツールが発行したIOのみを管理 |
| 6.9 | 監査ログ | すべてのパーミッション決定を記録、タイムスタンプ、リクエスター、リソース、結果付き |

**成果物**：ビーイングが機密操作を試行した際にパーミッションプロンプトが表示。

**検証**：ビーイングにファイル削除を指示 → コンソールにパーミッションプロンプト表示 → `n` を入力 → 操作が拒否される。ビーイングにホワイトリストサイトへのアクセスを指示 → 即座に許可。
