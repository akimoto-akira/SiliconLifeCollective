## 개요

Web UI는 실리콘 비잉 관리, 시스템 상태 모니터링 및 AI 에이전트와의 상호작용을 위한 종합적인 인터페이스를 제공합니다. 시스템은 순수 서버 사이드 렌더링 아키텍처를 채택하고 있으며, 프론트엔드 프레임워크 의존성이 없고 `H`, `CssBuilder` 및 `JsBuilder` 빌더를 통해 HTML, CSS 및 JavaScript를 생성합니다.

## 접속

기본 URL: `http://localhost:8080`

## 내비게이션

### 주요 섹션

1. **대시보드** - 시스템 개요 및 지표
2. **비잉** - 실리콘 비잉 관리
3. **채팅** - 비잉과의 상호작용 (파일 업로드, 실시간 SSE 지원)
4. **채팅 기록** - 실리콘 비잉의 채팅 기록 조회 (세션 목록, 메시지 상세)
5. **태스크** - 태스크 관리 (개인 태스크)
6. **타이머** - 타이머 설정 (생성, 일시정지, 실행 기록)
7. **설정** - 시스템 설정 (AI 클라이언트, 로컬라이제이션)
8. **권한** - 접근 제어 (ACL 관리, 권한 조회)
9. **로그** - 시스템 로그 (레벨별 필터, 시간 범위 조회)
10. **감사** - 토큰 사용 및 감사 추적
11. **메모리** - 비잉 메모리 (타임라인 뷰, 고급 필터)
12. **지식** - 지식 베이스 (트리플렛 관리, 경로 탐색)
13. **코드 브라우저** - 코드 탐색 (파일 트리, 구문 하이라이팅)
14. **코드 편집기** - 호버 팁이 있는 코드 편집 (Monaco Editor)
15. **프로젝트** - 프로젝트 관리 (워크스페이스, 태스크, 워크 노트)
16. **이그제큐터** - 이그제큐터 관리 (디스크, 네트워크, 커맨드라인)
17. **도움말** - 도움말 문서 시스템 (다국어 지원, 주제 검색)
18. **정보** - 시스템 정보 및 버전

### IM 플랫폼 (다중 인스턴스)

IM 플랫폼 설정은 다중 인스턴스 아키텍처를 지원하며, 여러 플랫폼을 동시에 활성화할 수 있습니다:

1. **플랫폼 추가**를 클릭하고 플랫폼 타입을 선택합니다:
   - **Web UI** (내장, 기본 활성화)
   - **Feishu** (수동 설정 및 OAuth 원클릭 인증 지원)
   - **WeChat Enterprise** (수동 설정)
   - **DingTalk** (수동 설정, Stream / HTTP 두 가지 이벤트 모드 지원)
2. 동적 폼에 플랫폼 필드 입력 (필수 항목은 별표 표시, 시크릿 필드는 비밀번호 입력란)
3. 각 인스턴스는 독립적으로 활성화/비활성화, 삭제 가능

**시크릿 환경 변수**: 설정 값은 `${ENV_VAR}` 플레이스홀더를 지원합니다 (예: `"${FEISHU_APP_SECRET}"`). 런타임에 환경 변수에서 해석되며, 평문 시크릿은 config.json에 기록되지 않습니다.

**OAuth 인증 마법사** (Feishu): appId/appSecret 저장 후, 설정 페이지에 인라인 인증 영역이 나타납니다. **인증** 버튼을 클릭하면 시스템 브라우저가 열리고 Feishu 인증 페이지로 이동합니다. 인증 완료 후 토큰이 자동으로 설정에 기록되며, 페이지는 SSE를 통해 실시간으로 인증 상태(성공/실패/타임아웃)를 표시합니다. 수동 복사-붙여넣기가 필요 없습니다.

### MCP 서버

MCP 서버 목록은 설정 페이지에서 중앙 관리됩니다 (배열 편집기): 각 행에 하나의 서버(ID, 이름, 전송 방식 stdio/http, 명령 또는 엔드포인트, 활성 상태)가 표시되며, 인라인 **추가** 및 **삭제**를 지원합니다. 저장 후 서버가 즉시 연결되며, 해당 툴이 실리콘 비잉에 자동 주입됩니다. 자세한 내용은 아래 [MCP 관리](#mcp-관리) 섹션을 참조하세요.

### 스토리지 설정

- Default 버전: 기본 경로, 시간 인덱스, 정리 정책
- Fast 버전: SpeedyPack 스토리지 엔진 설정, .spk 파일 관리, 자동 컴팩션 설정

## 권한 관리

### 권한 조회

- 모든 권한 규칙 나열
- 사용자 또는 리소스별 필터
- 만료 날짜 확인

### 권한 규칙 추가

1. **규칙 추가** 클릭
2. 설정:
   - 퍼미션 타입 (예: `FileAccess`, `NetworkAccess`)
   - 리소스 접두사 (예: `C:\Projects`, `api.github.com`)
   - 허용/거부
   - 설명
3. 저장

### 감사 추적

모든 권한 결정을 확인합니다:
- 타임스탬프
- 사용자
- 리소스
- 결정
- 사유

### 툴 권한 관리

실리콘 비잉 및 프로젝트의 툴 조작 권한을 관리합니다:

1. **실리콘 비잉 툴 권한**:
   - **비잉** → 비잉 선택 → **툴 권한**으로 이동
   - 현재 권한 설정 확인
   - 조작별로 허용/거부 설정
   - 권한 템플릿 적용 (readonly/restricted/full)

2. **프로젝트 툴 권한**:
   - **프로젝트** → 프로젝트 선택 → **툴 권한**으로 이동
   - 프로젝트 수준의 툴 권한은 실리콘 비잉 수준과 독립적
   - 프로젝트 간 권한 격리 구현

## 채팅 기록 조회

### 기능

- 실리콘 비잉 채팅 기록 탐색
- 세션 목록 표시
- 메시지 상세 조회
- 타임라인 뷰

### 채팅 기록 사용법

1. **비잉** 페이지로 이동
2. 실리콘 비잉의 **채팅 기록** 링크 클릭
3. 세션 목록 확인:
   - 세션 제목
   - 생성 시간
   - 메시지 수
4. 세션을 클릭하여 상세 확인:
   - 전체 메시지 기록
   - 타임스탬프
   - 발신자 정보
   - 툴 콜 기록

### 기술 구현

- **컨트롤러**: `ChatHistoryController`
- **뷰 모델**: `ChatHistoryViewModel`
- **뷰**:
  - `ChatHistoryListView` - 세션 목록
  - `ChatHistoryDetailView` - 메시지 상세
- **API 라우트**:
  - `/api/chat-history/{beingId}/conversations` - 세션 목록 조회
  - `/api/chat-history/{beingId}/conversation/{conversationId}` - 메시지 상세 조회

## 도움말 문서 시스템 (신규)

### 기능 개요

도움말 문서 시스템은 실리콘 비잉과 사용자에게 다국어 도움말 문서 지원을 제공합니다.

### 도움말 문서 사용법

1. **도움말** 페이지로 이동
2. 도움말 주제 목록 확인:
   - 빠른 시작 가이드
   - 툴 사용 참조
   - 권한 관리 가이드
   - 문제 해결 매뉴얼
   - 개발 가이드
3. 주제를 클릭하여 상세 내용 확인:
   - 구조화된 문서 콘텐츠 (Markdown 렌더링)
   - 다국어 지원 (시스템 로컬라이제이션 설정 따름)
   - 관련 주제 추천
4. 검색 기능으로 빠르게 찾기:
   - 키워드 검색 (한국어, 영어 지원)
   - 검색 결과 관련도 순 정렬

### 실리콘 비잉의 도움말 접근

실리콘 비잉은 `help` 툴을 통해 도움말 문서에 접근할 수 있습니다:
```json
{
  "action": "get_topics"
}
```

### 기술 구현

- **컨트롤러**: `HelpController`
- **툴**: `HelpTool`
- **API 라우트**:
  - `/api/help` - 도움말 주제 목록 조회
  - `/api/help/{topicId}` - 주제 상세 조회
  - `/api/help/search?q=keyword` - 도움말 문서 검색

## 프로젝트 워크스페이스 (신규)

### 기능 개요

프로젝트 워크스페이스는 구조화된 작업 환경을 제공하여 프로젝트 관리, 태스크 추적 및 워크 노트를 지원합니다.

### 프로젝트 관리

1. **프로젝트 생성**:
   - 프로젝트 이름 및 설명
   - 프로젝트 태그 (분류)
   - 프로젝트 상태 (진행 중, 완료, 보관됨)
2. **프로젝트 상세 조회**:
   - 프로젝트 기본 정보
   - 관련 태스크 목록
   - 워크 노트 목록
   - 프로젝트 진행 통계
3. **프로젝트 보관**: 기록 데이터는 유지하되 더 이상 활성화하지 않음
4. **프로젝트 역할 관리**:
   - 실리콘 비잉에 프로젝트 역할 할당 (예: developer, reviewer, manager)
   - 역할 할당 제거
   - 프로젝트 멤버 및 역할 목록 확인
5. **프로젝트 워크플로우**:
   - 워크플로우 템플릿 목록 확인
   - 프로젝트에 워크플로우 템플릿 바인딩
   - 워크플로우 인스턴스 상태 확인
   - 워크플로우 실행 로그 확인

### 워크 노트 (비공개)

실리콘 비잉의 개인 워크 노트로, 일기장과 유사합니다:

1. **노트 생성**:
   - 요약 (간단한 설명)
   - 내용 (Markdown 형식 지원)
   - 키워드 (검색용)
   - 자동 타임스탬프 기록
2. **노트 관리**:
   - 타임라인으로 탐색 (페이지 디자인)
   - 노트 검색 (키워드, 요약, 내용별)
   - 목차 생성 (노트 구조 빠르게 탐색)
   - 노트 업데이트 및 삭제
3. **권한 제어**:
   - 기본적으로 비공개이며, 비잉 본인만 접근 가능
   - 실리콘 큐레이터는 모든 노트를 관리할 수 있음

### 기술 구현

- **컨트롤러**: `WorkNoteController`
- **툴**: `WorkNoteTool`, `ProjectTool`, `ProjectWorkNoteTool`
- **API 라우트**:
  - `/api/worknotes` - 워크 노트 목록 조회
  - `/api/worknotes/{id}` - 노트 상세 조회
  - `/api/worknotes/search?q=keyword` - 노트 검색
  - `/api/worknotes/directory` - 노트 목차 생성
  - `/api/projects` - 프로젝트 관리 API

## 스킬 관리

### 기능 개요

스킬(Skill)은 "툴 오케스트레이션 + 프롬프트 템플릿"의 재사용 가능한 능력 단위입니다. 스킬 관리 페이지(`/skill?beingId={id}`)는 각 실리콘 비잉에 스킬의 시각적 관리를 제공합니다.

### 페이지 레이아웃

- **좌측 스킬 목록**: 카드형 표시 (제목, `버전 · 출처 · 트리거 모드` 배지, 설명)
- **우측 편집기**: Markdown 편집기 (YAML 프론트매터 + 프롬프트 본문)
- **상단 통계**: 스킬 총수 / 커스텀 스킬 수 / 할당량 상한 (예: `5 / 2 / 50`)

### 툴바 조작

- **새로 만들기**: Markdown 스킬 템플릿 로드
- **.md 가져오기 / .json 가져오기**: 로컬 파일에서 스킬 가져오기
- **새로고침**: 스킬 목록 재로드

### 스킬 카드 조작

각 스킬 카드는 5개의 조작을 제공합니다:

| 조작 | 설명 |
|------|------|
| 편집 | 우측 편집기에서 Markdown을 열어 저장(upsert) 가능 |
| 테스트 | 매개변수 JSON 입력, 스킬을 즉시 한 번 실행하고 결과 확인 |
| JSON 내보내기 | `{id}.json` 다운로드 |
| Markdown 내보내기 | `{id}.md` 다운로드 |
| 삭제 | 스킬 삭제 (영속화 파일 포함) |

### 스킬 작성

스킬은 Markdown으로 작성되며, YAML 프론트매터에 id, 설명, 매개변수 schema, 툴 화이트리스트, 트리거 모드 등을 선언합니다. 본문은 프롬프트 템플릿(`{param}` 플레이스홀더 지원)입니다. 본문만 작성(YAML 생략)해도 됩니다 — 저장 시 AI가 누락된 메타데이터를 자동 보완하며, 사용자가 제공한 필드는 결코 덮어쓰지 않습니다.

```markdown
---
id: daily_news_digest
description: 오늘의 기술 뉴스를 검색하고 요약을 생성
tool_whitelist: [network, work_note]
trigger_mode: Auto
metadata:
  schedule: "0 9 * * *"
---

network 툴을 사용하여 {topic}의 최신 뉴스를 검색하고, 500자 요약을 생성하여 워크 노트에 저장하세요.
```

### 기술 구현

- **컨트롤러**: `SkillController` (페이지 + 10개 API 엔드포인트)
- **코어**: `SkillManager` (등록/실행/핫 리로드), `SkillMetadataCompleter` (AI 메타데이터 보완)
- **핫 리로드**: 비잉은 30초마다 `skills/` 디렉토리 변경을 감지, Web UI 저장 후 재시작 불필요
- **버전 아카이브**: 각 업데이트 시 `skills/archive/{id}/{version}.md`에 자동 아카이브

## MCP 관리

### 기능 개요

MCP(Model Context Protocol, 모델 컨텍스트 프로토콜) 관리 페이지(`/mcp`)는 외부 MCP 서버 연결을 관리하는 데 사용됩니다. 연결 후, 서버가 제공하는 툴은 `mcp_{서버ID}_{툴명}` 형식으로 모든 실리콘 비잉에 자동 주입됩니다.

### 서버 목록

각 서버의 ID, 이름, 전송 방식(stdio/http), 연결 상태(connected/disconnected/connecting/error), 활성 상태, 툴 수, 최근 오류를 표시합니다.

### 관리 조작

| 조작 | 설명 |
|------|------|
| 서버 추가 | ID(소문자/숫자/언더스코어), 이름, 전송 방식 입력; stdio는 명령과 인수 필요, http는 엔드포인트 URL 필요 |
| 활성화/비활성화 | 인라인 토글, 비활성화 시 툴이 모든 비잉에서 등록 해제 |
| 재연결 | 연결 해제 후 재연결, 툴 목록 새로고침 |
| 삭제 | 서버 설정 및 모든 툴 제거 |
| 툴 조회 | 서버를 펼쳐 툴명(접두사 포함), 설명, 매개변수 schema 나열 |
| 툴 테스트 | 특정 MCP 툴을 직접 호출하여 연결성 검증(AI 개입 불필요) |

### stdio 서버 추가 예시

```json
{
  "id": "filesystem",
  "name": "Filesystem",
  "transport": "stdio",
  "command": "npx",
  "arguments": ["-y", "@modelcontextprotocol/server-filesystem", "/data"],
  "enabled": true
}
```

### 보안 메커니즘

- 서버의 추가/삭제/활성화/비활성화는 사용자가 Web UI를 통해서만 수행 가능, AI는 서버 목록을 수정할 수 없음 (`mcp` 툴은 읽기 전용 쿼리만 제공)
- MCP 래핑 툴은 툴 권한 매트릭스에서 단일 `execute` 액션으로 표현되며, 비잉/프로젝트별로 개별 비활성화 가능
- 글로벌 스위치 `McpEnabled`로 전체 MCP 통합을 원클릭 비활성화 가능

## 문제 해결

### 연결 불가

**확인 사항**:
- 서버가 실행 중인지 확인
- 포트 8080이 차단되지 않았는지 확인
- 방화벽 설정 확인

### SSE 작동 안 함

**확인 사항**:
- 브라우저가 SSE를 지원하는지 확인
- 프록시가 SSE를 버퍼링하지 않는지 확인
- 네트워크 안정성 확인

### 성능 저하

**최적화**:
- 로그 상세 수준 낮추기
- 오래된 감사 데이터 정리
- 시스템 리소스 확인
