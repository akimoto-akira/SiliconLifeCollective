Кремниевые Существа — это AI-управляемые агенты, способные автономно мыслить, действовать и эволюционировать.

## Жизненный цикл существа

### Активные состояния

Кремниевые Существа имеют следующие активные состояния:

| Состояние | Описание |
|------|------|
| `Idle` | Состояние ожидания, ожидание тактового запуска |
| `SingleChat` | Ведение индивидуального чата |
| `GroupChat` | Ведение группового чата |
| `Task` | Выполнение задачи |
| `Timer` | Выполнение таймера |
| `Broadcast` | Обработка широковещательного сообщения |
| `Project` | Работа над проектом |
| `MemoryCompression` | Сжатие памяти |
| `Stopped` | Остановлено из-за последовательных ошибок или ручной остановки |

**Механизм состояния Stopped**:
- Когда Кремниевое Существо совершает 10 последовательных ошибок, оно автоматически переходит в состояние `Stopped`
- После перехода в состояние Stopped существо больше не выполняет никаких задач
- При поступлении нового чат-сообщения счётчик ошибок сбрасывается, и существо возобновляет работу
- Также возможен ручной перезапуск

### Переходы состояний

```
Idle → SingleChat → Idle (чат завершён)
Idle → GroupChat → Idle (групповой чат завершён)
Idle → Task → Idle (задача завершена)
Idle → Timer → Idle (таймер завершён)
Idle → Broadcast → Idle (широковещание обработано)
Idle → Project → Idle (работа над проектом завершена)
Idle → MemoryCompression → Idle (сжатие памяти завершено)
Любое → Stopped (10 последовательных ошибок)
Stopped → Idle (новое чат-сообщение или ручной перезапуск)
```

### Операции

- **Запуск**: инициализация и начало обработки
- **Остановка**: корректное завершение
- **Перезапуск**: восстановление из состояния Stopped в Idle

## Система Задач

### Создание задачи

```csharp
var task = new BeingTask
{
    BeingId = being.Id,
    Description = "Review the code",
    Priority = 5,
    DueDate = DateTime.UtcNow.AddHours(2)
};

await taskSystem.CreateAsync(task);
```

### Статусы задач

- `Pending` - ожидание выполнения
- `Running` - выполняется
- `SubmittedForReview` - отправлено на проверку
- `UnderReview` - на проверке
- `Rework` - доработка
- `Completed` - успешно завершено
- `Failed` - ошибка выполнения
- `Cancelled` - отменено вручную

## Система Таймеров

### Типы таймеров

1. **Одноразовый**: выполнение один раз после задержки
2. **Интервальный**: повторение с фиксированным интервалом
3. **Cron**: выполнение на основе cron-выражения

### Пример

```csharp
// Выполнять каждый час
var timer = new BeingTimer
{
    BeingId = being.Id,
    Interval = TimeSpan.FromHours(1),
    Action = "think",
    Repeat = true
};

await timerSystem.StartAsync(timer);
```

## Система навыков

Навык (Skill) — это переиспользуемая единица возможностей Кремниевого Существа: «оркестрация инструментов + шаблон промпта» инкапсулируется в объявляемую, эволюционируемую, автоматически планируемую функцию. AI вызывает навык так же, как обычный инструмент.

### Структура навыка

| Элемент | Описание |
|---------|----------|
| `id` / `description` | Уникальный идентификатор и описание в одном предложении (показывается AI, определяет, когда AI выберет этот навык) |
| `parameter_schema` | JSON Schema параметров, объявляет каждый заполнитель `{param}`, используемый в промпте |
| `system_prompt_template` | Шаблон системного промпта, при выполнении заполняется параметрами |
| `tool_whitelist` | Список инструментов, разрешённых во время выполнения (пустой = наследование всех инструментов существа) |
| `max_tool_round` / `timeout` | Лимиты раундов инструментов и тайм-аута (ограничиваются глобальными верхними пределами) |
| `on_complete` | Действие при завершении: `none` / `write_memory` / `notify_curator` / `broadcast` |
| `trigger_mode` | `Manual` (автономный вызов AI) или `Auto` + расписание `schedule` |

### Четыре источника

- **Builtin** — встроенные в фреймворк (`summarize_document` — summaries документов, `code_review` — ревью кода, `research_topic` — исследование темы)
- **Plugin** — регистрируются плагинами через `ISkillProvider`
- **Being** — создаются существом во время выполнения через инструмент `skill`
- **User** — создаются пользователем через страницу управления навыками в Web UI

### Способы запуска

1. **Ручной (Manual)**: навык внедряется как обычное определение инструмента в запрос AI, AI сам решает, когда его вызвать; планировщик приоритетно направляет одноимённые вызовы к навыку
2. **Автоматический (Auto + schedule)**: выражение расписания хранится в `metadata.schedule`, поддерживаются три формата:
   - `"09:30"` — ежедневное фиксированное время
   - `"6h"` / `"30m"` / `"2d"` — интервальный период
   - `"0 9 * * *"` / `"*/15 * * * *"` — подмножество cron

### Написание в Markdown

Навыки хранятся в Markdown (`skills/{id}.md`, метаданные YAML front matter + текст промпта):

```markdown
---
id: daily_news_digest
description: Поиск сегодняшних технических новостей и генерация сводки
tool_whitelist: [network, work_note]
on_complete: write_memory
---

Используйте инструмент network для поиска последних новостей по теме {topic}, сгенерируйте сводку на 500 слов и сохраните в рабочие заметки.
```

Можно написать только текст (опустить YAML): при сохранении AI автоматически дополнит метаданные — id, description, схему параметров и т.д. Поля, уже заполненные пользователем, никогда не перезаписываются.

### Самоуправление существа

Существо может управлять своей библиотекой навыков через инструмент `skill`:

```json
{ "action": "list" }
{ "action": "create", "id": "my_skill", "system_prompt": "...", "description": "..." }
{ "action": "update_from_md", "skill_id": "my_skill", "markdown": "..." }
{ "action": "delete", "skill_id": "my_skill" }
```

### Горячая перезагрузка и эволюция

- Существо каждые 30 секунд проверяет изменения в каталоге `skills/` (сравнение отпечатков); изменения из Web UI или других существ вступают в силу автоматически, без перезапуска
- При каждом обновлении навыка автоматически архивируется историческая версия в `skills/archive/{id}/{version}.md`, образуя историю эволюции навыка
- Количество пользовательских навыков ограничено квотой (`MaxCustomSkillsPerBeing`, по умолчанию 50)

### Ограждения выполнения

- Разрешение на действие `execute` на уровне навыка (может быть отключено матрицей разрешений; отключённые навыки невидимы для AI)
- Параметры выполнения ограничиваются глобальными верхними пределами: раунды ≤ `GlobalMaxToolRound` (по умолчанию 10), тайм-аут ≤ `GlobalSkillTimeoutSeconds` (по умолчанию 300 секунд)
- Навык не может рекурсивно вызвать сам себя
- Вызовы инструментов вне белого списка немедленно отклоняются

## Система рабочих заметок

### Обзор

Рабочие заметки — это система личного дневника Кремниевого Существа с постраничным дизайном для записи рабочего прогресса, обучающих заметок, проектных записей и т.д.

### Возможности

- **Постраничное управление**: каждая заметка представляет собой отдельную страницу, доступ к которой осуществляется по номеру
- **Поддержка Markdown**: содержимое поддерживает формат Markdown (текст, списки, таблицы, блоки кода)
- **Индекс по ключевым словам**: поддержка добавления ключевых слов к заметкам для удобного поиска
- **Функция резюме**: каждая заметка имеет краткое описание для быстрого просмотра
- **Генерация каталога**: возможность создания обзора каталога всех заметок для понимания общего контекста
- **Метки времени**: автоматическая запись времени создания и обновления
- **По умолчанию приватные**: доступно только самому существу (Куратор может управлять)

### Сценарии использования

1. **Запись прогресса проекта**
   ```
   Резюме: Завершён модуль аутентификации пользователей
   Содержание: Реализована проверка JWT token, интеграция OAuth2, механизм обновления token
   Ключевые слова: аутентификация,JWT,OAuth2
   ```

2. **Учебные заметки**
   ```
   Резюме: Изучение лучших практик асинхронного программирования на C#
   Содержание: Замечания по использованию async/await, сценарии использования ConfigureAwait...
   Ключевые слова: C#,асинхронность,лучшие практики
   ```

3. **Протоколы встреч**
   ```
   Резюме: Обсуждение требований к продукту
   Содержание: Обсуждались требования к новым функциям, определён план реализации...
   Ключевые слова: продукт,требования,встреча
   ```

### Использование через инструмент

Существа могут управлять рабочими заметками через инструмент `work_note`:

```json
// Создание заметки
{
  "action": "create",
  "summary": "Завершён модуль аутентификации пользователей",

  "keywords": "аутентификация,JWT,OAuth2"

// Чтение заметки
{
  "action": "read",
```

## Сеть Знаний

### Обзор

Сеть Знаний — это система представления и управления знаниями на основе структуры триплетов (субъект-предикат-объект), предназначенная для хранения и управления структурированными знаниями.

### Основные концепции

#### Структура триплетов

```
Субъект (Subject) --Предикат (Predicate)--> Объект (Object)
```

**Примеры**:
- `Python` --`is_a`--> `programming_language`
- `Пекин` --`capital_of`--> `Китай`
- `Вода` --`boiling_point`--> `100°C`

#### Оценка достоверности

Каждый триплет знаний имеет оценку достоверности (0.0-1.0), указывающую на надёжность знания:
- `1.0`: абсолютная уверенность (например, математическая теорема)
- `0.8-0.99`: высокая достоверность (например, проверенные факты)
- `0.5-0.79`: средняя достоверность (например, выводы или гипотезы)
- `<0.5`: низкая достоверность (например, догадки или непроверенная информация)

#### Система тегов

Поддержка добавления тегов к триплетам для классификации и поиска:
```json
{
  "subject": "Python",
  "predicate": "is_a",
  "object": "programming_language",
  "tags": ["programming", "language", "popular"]
}
```

### Операции со знаниями

#### 1. Добавление знаний

```json
{
  "action": "add",
  "subject": "C#",
  "predicate": "created_by",
  "object": "Microsoft",
  "confidence": 1.0,
  "tags": ["programming", "language"]
}
```

#### 2. Запрос знаний

```json
{
  "action": "query",
  "subject": "C#",
  "predicate": "created_by"
}
```

#### 3. Поиск знаний

```json
{
  "action": "search",
  "query": "programming language",
  "limit": 10
}
```

#### 4. Обнаружение путей знаний

Обнаружение связей между двумя концепциями:
```json
{
  "action": "get_path",
  "from": "Python",
  "to": "computer_science"
}
```

Возвращает:
```
Python → is_a → programming_language → belongs_to → computer_science
```

#### 5. Валидация знаний

Проверка валидности и согласованности знаний:
```json
{
  "action": "validate",
  "subject": "Python",
  "predicate": "is_a",
  "object": "programming_language"
}
```

#### 6. Статистика знаний

Получение общей статистики Сети Знаний:
```json
{
  "action": "stats"
}
```

Возвращает:
```json
{
  "totalTriples": 1523,
  "totalSubjects": 450,
  "totalPredicates": 85,
  "totalObjects": 892,
  "averageConfidence": 0.87
}
```

### Сценарии использования

1. **Хранение фактов**
   - Хранение объективных фактов и общих знаний
   - Пример: `Земля` --`is_a`--> `планета`

2. **Отношения между концепциями**
   - Запись отношений между концепциями
   - Пример: `наследование` --`is_a`--> `концепция объектно-ориентированного программирования`

3. **Накопление знаний**
   - Существа постоянно накапливают знания через обучение
   - Формирование структурированной системы знаний

4. **Поддержка рассуждений**
   - Обнаружение косвенных связей через пути знаний
   - Поддержка рассуждений и принятия решений на основе знаний

### Управление через Web UI

1. Перейдите на страницу **Сеть Знаний**
2. Просмотр статистики знаний
3. Поиск и просмотр знаний
4. Визуализация графа знаний (в планах)

## Операции WebView браузера (новое)

### Обзор

Кремниевые Существа могут автономно просматривать веб-страницы, получать информацию и выполнять веб-операции через инструмент WebView браузера. Браузер работает в безголовом режиме, полностью невидимом для пользователя.

### Возможности

- **Индивидуальная изоляция**: каждое существо имеет независимый экземпляр браузера, Cookie и хранилище сессий
- **Безголовый режим**: автономная работа в фоновом режиме, невидимо для пользователя
- **Полная функциональность**: поддержка выполнения JavaScript, рендеринга CSS, заполнения форм и др.
- **Контроль безопасности**: все операции проходят через цепочку проверки разрешений

### Часто используемые операции

#### 1. Открытие браузера

```json
{
  "action": "open"
}
```

#### 2. Навигация на веб-страницу

```json
{
  "action": "navigate",
  "url": "https://example.com"
}
```

#### 3. Получение содержимого страницы

```json
{
  "action": "get_page_text"
}
```

Возвращает текстовое содержимое страницы для анализа и понимания AI.

#### 4. Клик по элементу

```json
{
  "action": "click",
  "selector": "#submit-button"
}
```

#### 5. Ввод текста

```json
{
  "action": "input",
  "selector": "#search-input",
  "text": "ключевое слово для поиска"
}
```

#### 6. Выполнение JavaScript

```json
{
  "action": "execute_script",
  "script": "return document.title;"
}
```

#### 7. Получение скриншота

```json
{
  "action": "get_screenshot"
}
```

Возвращает скриншот страницы (Base64-кодированный), может использоваться для визуального анализа.

#### 8. Ожидание появления элемента

```json
{
  "action": "wait_for_element",
  "selector": ".loading-complete",
  "timeout": 10000
}
```

### Сценарии использования

1. **Получение информации**
   - Просмотр новостных сайтов для получения последних новостей
   - Запрос документации и технических материалов
   - Мониторинг изменений содержимого веб-страниц

2. **Автоматизация операций**
   - Заполнение и отправка форм
   - Нажатие кнопок для запуска операций
   - Сбор данных с веб-страниц

3. **Анализ веб-страниц**
   - Анализ структуры и содержимого страницы
   - Извлечение определённой информации
   - Визуальный анализ скриншотов страниц

### Меры предосторожности

- Операции браузера могут быть медленными, необходимо дождаться загрузки страницы
- Используйте `wait_for_element` для обеспечения появления элемента перед операцией
- Соблюдайте условия использования сайтов и robots.txt
- Избегайте частых запросов, которые могут привести к блокировке

## Лучшие практики

### Написание Файла Души

1. **Конкретность**: чёткие личностные характеристики и границы
2. **Определение области**: что существо должно и не должно делать
3. **Включение примеров**: демонстрация ожидаемых моделей поведения
4. **Регулярное обновление**: эволюция Файла Души на основе результатов

### Управление задачами

1. **Установка приоритетов**: использование приоритетов (1-10)
2. **Определение сроков**: всегда устанавливайте сроки выполнения
3. **Мониторинг прогресса**: регулярно проверяйте статус задач
4. **Обработка сбоев**: реализация логики повторных попыток

### Оптимизация памяти

1. **Очистка старых данных**: регулярная архивация старых воспоминаний
2. **Индексирование важной информации**: пометка ключевой информации
3. **Использование хранилища с временным индексом**: использование запросов с временным индексом

### Механизм затухания памяти

Система включает встроенную службу `MemoryFadeService` периодического затухания, моделирующую характеристику забывания биологической памяти:

- **Автоматическое затухание**: каждый час применяется алгоритм затухания важности к записям памяти всех Кремниевых Существ
- **Автоматическая архивация**: память с важностью ниже порога автоматически архивируется и больше не участвует в повседневном поиске
- **Отслеживание статистики**: запись количества циклов затухания и количества записей с изменённым состоянием

Это означает, что память Кремниевых Существ естественным образом затухает со временем, и важную информацию необходимо активно помечать как высокую важность через инструмент памяти, чтобы избежать автоматической архивации.

## Рабочее пространство проекта

### Обзор

Рабочее пространство проекта — это механизм управления пространством для поддержки сотрудничества нескольких Кремниевых Существ. Кремниевый Куратор может создавать проектные пространства, назначать Кремниевых Существ в проекты и распределять для них роли.

### Жизненный цикл проекта

```
Создание → Активность → Архивация → Уничтожение
              ↑       |
              └─ Восстановление ┘
```

### Роли в проекте

Кремниевым Существам могут быть назначены определённые роли в проекте:

```json
{
  "action": "assign_role",
  "project_id": "project-uuid",
  "being_id": "being-uuid",
  "role_name": "developer"
}
```

### Рабочие заметки проекта

Рабочие заметки в проектном пространстве являются общедоступными, все участники проекта имеют к ним доступ:

```json
{
  "action": "create",
  "project_id": "project-uuid",
  "summary": "Завершён модуль аутентификации пользователей",
  "content": "## Детали реализации\n\n- Использование JWT token",
  "keywords": "аутентификация,JWT"
}
```

### Задачи проекта

Задачи в проектном пространстве поддерживают полное управление жизненным циклом:

```json
{
  "action": "create",
  "project_id": "project-uuid",
  "title": "Реализация аутентификации пользователей",
  "priority": 5
}
```

### Рабочие процессы проекта

Проекты могут быть привязаны к шаблонам рабочих процессов для управления процессами сотрудничества Кремниевых Существ:

- Рабочие процессы основаны на шаблонах конечных автоматов
- Поддержка переходов состояний на основе Tick
- Автоматическая запись журнала переходов состояний

### Изоляция разрешений инструментов

Разрешения инструментов на уровне проекта независимы от разрешений на уровне Кремниевого Существа, обеспечивая изоляцию разрешений между проектами. Например, Кремниевое Существо может иметь разрешения на сетевой доступ в проекте A, но быть ограничено разрешениями только для чтения в проекте B.

## Устранение неполадок

### Существо не запускается

**Проверьте**:
- Файл Души существует и корректен
- AI-клиент настроен
- Системные ресурсы достаточны

### Существо неожиданно останавливается

**Проверьте**:
- Ошибки в журналах
- Доступность AI-сервиса
- Использование памяти

### Задачи не выполняются

**Проверьте**:
- Система таймеров работает
- Приоритет и расписание задач
- Настройки разрешений
