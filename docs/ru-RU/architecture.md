## Двухверсионная архитектура

Этот проект предоставляет две версии реализации, использующие одинаковую архитектуру, но различающиеся в хранении и оптимизации производительности:

### SiliconLife.Default (версия по умолчанию)
- **Назначение**: реализация по умолчанию, в основном для проверки жизнеспособности архитектуры
- **Режим работы**: консольное приложение
- **Способ хранения**: чистое хранение JSON в файловой системе
- **Сценарии применения**: высокий уровень безопасности данных, ограниченные ресурсы памяти, небольшой объём данных
- **Описание роли**: базовая реализация для проверки архитектуры, обеспечивает простой и надёжный способ работы, подходит для первого знакомства с проектом, отладки разработки или приоритета безопасности данных

### SiliconLife.Fast (высокопроизводительная версия)
- **Назначение**: основная производственная версия
- **Режим работы**: настольное приложение (системный трей Windows / окно состояния Linux)
- **Способ хранения**: хранение в памяти SpeedyPack + асинхронная пакетная персистентность (формат файла .spk)
- **Сценарии применения**: высокая параллельность, низкая задержка, большие объёмы данных
- **Поддержка платформ**: Windows/macOS (полная функциональность, включая системный трей), Linux (окно состояния, без значка в трее)
- **Особенности**:
  - Фоновая работа в системном трее Windows/macOS, мониторинг в реальном времени через окно состояния трея; прямое отображение окна состояния на Linux
  - Движок SpeedyPack + автоматическая компрессия гарантируют безопасность данных
  - Компонентная архитектура UI, 27 декларативных компонентов
  - 7 тем оформления, поддержка автоматического обнаружения и переключения
  - Инструмент горячей перезагрузки для онлайн-обновления и перезапуска
  - Linux автоматически открывает браузер для доступа к Web UI, поддержка параметра `--no-tray`
- **Повышение производительности**: задержка чтения хранилища снижена в 1000 раз, задержка записи снижена в 15000 раз
- **Описание роли**: глубоко оптимизированная производственная реализация с такими возможностями, как фоновая работа в системном трее, движок SpeedyPack + автоматическая компрессия, предпочтительный выбор для длительной работы и реальных производственных сред

> **Примечание**: архитектура, описанная в этом документе, применима к обеим версиям, за исключением реализации хранилища. SiliconLife.Default выступает в качестве базовой реализации для проверки архитектуры, а SiliconLife.Fast — в качестве основной производственной версии.

## Основные концепции

### Кремниевое Существо

Каждый AI-агент в системе является **Кремниевым Существом** — автономной сущностью с собственным идентитетом, личностью и возможностями. Каждое Кремниевое Существо управляется **Файлом Души** (подсказка в формате Markdown), определяющим его модели поведения.

### Кремниевый Куратор

**Кремниевый Куратор** — это специальное Кремниевое Существо с высшими системными полномочиями. Оно выступает в роли системного администратора:

- Создаёт и управляет другими Кремниевыми Существами
- Анализирует запросы пользователей и разбивает их на задачи
- Распределяет задачи между соответствующими Кремниевыми Существами
- Контролирует качество выполнения и обрабатывает ошибки
- Использует **приоритетное планирование** для ответа на сообщения пользователей (см. ниже)

### Файл Души

Markdown-файл (`soul.md`), хранящийся в каталоге данных каждого Кремниевого Существа. Он внедряется как системная подсказка в каждый AI-запрос, определяя личность существа, модели принятия решений и поведенческие ограничения.

## Планирование: справедливое планирование с временными интервалами

### Основной Цикл + Объекты Tick

Система запускает **управляемый часами Основной Цикл** на выделенном фоновом потоке:

```
Основной Цикл (выделенный поток, Сторожевой Таймер + Автоматический Выключатель)
  └── Объект Tick A (приоритет=0, интервал=100мс)
  └── Объект Tick B (приоритет=1, интервал=500мс)
  └── Менеджер Кремниевых Существ (прямой тактовый запуск от Основного Цикла)
        └── Бегун Кремниевого Существа → Существо 1 → Тактовый запуск → Выполнение раунда
        └── Бегун Кремниевого Существа → Существо 2 → Тактовый запуск → Выполнение раунда
        └── Бегун Кремниевого Существа → Существо 3 → Тактовый запуск → Выполнение раунда
        └── ...
```

Ключевые проектные решения:

- **Кремниевые Существа не наследуют Объекты Tick.** Они имеют собственный метод `Tick()`, вызываемый `SiliconBeingManager` через `SiliconBeingRunner`, а не регистрируются напрямую в Основном Цикле.
- **Менеджер Кремниевых Существ** запускается напрямую тактовым сигналом Основного Цикла и выступает как единый агент для всех существ.
- **Бегун Кремниевого Существа** оборачивает метод `Tick()` каждого существа во временном потоке с тайм-аутом и индивидуальным Автоматическим Выключателем (3 последовательных тайм-аута → 1 минута охлаждения).
- Выполнение каждого существа ограничено **одним раундом** AI-запроса + вызова инструментов за каждый тактовый запуск, что гарантирует, что ни одно существо не сможет монополизировать Основной Цикл.
- **Монитор Производительности** отслеживает время выполнения тактов для обеспечения наблюдаемости.

### Приоритетный ответ Куратора

Когда пользователь отправляет сообщение Кремниевому Куратору:

1. Текущее существо (например, Существо A) завершает текущий раунд — **без прерывания**.
2. Менеджер **пропускает оставшуюся очередь**.
3. Цикл **начинается заново с Куратора**, обеспечивая его немедленное выполнение.

Это гарантирует отзывчивость на взаимодействие с пользователем без нарушения текущих задач.

## Система Чата

### Типы сессий

Система чата через `SessionBase` поддерживает три типа сессий:

| Тип | Класс | Описание |
|------|-------|-------------|
| `SingleChat` | `SingleChatSession` | Диалог один на один между двумя участниками |
| `GroupChat` | `GroupChatSession` | Многопользовательский групповой чат |
| `Broadcast` | `BroadcastChannel` | Открытый канал с фиксированным ID; существа динамически подписываются и получают сообщения только после подписки |

### Широковещательный Канал

`BroadcastChannel` — это особый тип сессии для системных объявлений:

- **Фиксированный ID канала** — в отличие от `SingleChatSession` и `GroupChatSession`, ID канала является хорошо известной константой, а не производным от GUID участников.
- **Динамическая подписка** — существа подписываются/отписываются во время выполнения; они получают только сообщения, опубликованные после подписки.
- **Фильтрация ожидающих сообщений** — `GetPendingMessages()` возвращает только сообщения, опубликованные после времени подписки существа и ещё не прочитанные.
- **Управление Системой Чата** — `GetOrCreateBroadcastChannel()`, `Broadcast()`, `GetPendingBroadcasts()`.

### Чат-сообщения

Модель `ChatMessage` содержит поля для контекста AI-диалога и отслеживания токенов:

| Поле | Тип | Описание |
|-------|------|-------------|
| `Id` | `Guid` | Уникальный идентификатор сообщения |
| `SenderId` | `Guid` | Уникальный идентификатор отправителя |
| `ChannelId` | `Guid` | Идентификатор канала/диалога |
| `Content` | `string` | Содержание сообщения |
| `Timestamp` | `DateTime` | Время отправки сообщения |
| `Type` | `MessageType` | Текст, изображение, файл или системное уведомление |
| `ReadBy` | `List<Guid>` | ID участников, прочитавших это сообщение |
| `Role` | `MessageRole` | Роль в AI-диалоге (пользователь, помощник, инструмент) |
| `ToolCallId` | `string?` | ID вызова инструмента для сообщения с результатом инструмента |
| `ToolCallsJson` | `string?` | Сериализованный JSON вызовов инструментов для сообщения помощника |
| `Thinking` | `string?` | Цепочка рассуждений AI |
| `PromptTokens` | `int?` | Количество токенов в подсказке (входные) |
| `CompletionTokens` | `int?` | Количество токенов в дополнении (выходные) |
| `TotalTokens` | `int?` | Общее количество использованных токенов (входные + выходные) |
| `FileMetadata` | `FileMetadata?` | Прикреплённые метаданные файла (если сообщение содержит файл) |

### Очередь чат-сообщений

`ChatMessageQueue` — потокобезопасная система очереди сообщений для управления асинхронной обработкой чат-сообщений:

- **Потокобезопасность** — использование механизмов блокировки для безопасного параллельного доступа
- **Асинхронная обработка** — поддержка асинхронной постановки и извлечения сообщений из очереди
- **Упорядочивание сообщений** — сохранение хронологического порядка сообщений
- **Пакетные операции** — поддержка пакетного получения сообщений

### Метаданные файла

`FileMetadata` используется для управления информацией о файлах, прикреплённых к чат-сообщениям:

- **Информация о файле** — имя, размер, тип, путь файла
- **Время загрузки** — метка времени загрузки файла
- **Загрузивший** — ID пользователя или Кремниевого Существа, загрузившего файл

### Менеджер отмены потока

`StreamCancellationManager` предоставляет механизм отмены потоковых AI-ответов:

- **Управление потоком** — поддержка отмены текущего потокового AI-ответа
- **Очистка ресурсов** — корректная очистка связанных ресурсов при отмене
- **Параллельная безопасность** — поддержка одновременного управления несколькими потоками

### Просмотр истории чата

Новая функция просмотра истории чата позволяет пользователям просматривать исторические диалоги Кремниевых Существ:

- **Список сессий** — отображение всех исторических сессий
- **Детали сообщений** — просмотр полной истории сообщений
- **Временная шкала** — отображение сообщений в хронологическом порядке
- **Поддержка API** — предоставление RESTful API для получения данных сессий и сообщений

## Система AI-клиентов

Система поддерживает несколько AI-бэкендов через интерфейс `IAIClient`:

### OllamaClient

- **Тип**: локальный AI-сервис
- **Протокол**: нативный Ollama HTTP API (`/api/chat`, `/api/generate`)
- **Функции**: потоковая передача, вызов инструментов, локальный хостинг моделей
- **Конфигурация**: `endpoint`, `model`, `temperature`, `maxTokens`

### DashScopeClient (Alibaba Cloud Bailian)

- **Тип**: облачный AI-сервис
- **Протокол**: API, совместимый с OpenAI (`/compatible-mode/v1/chat/completions`)
- **Аутентификация**: Bearer token (API-ключ)
- **Функции**: потоковая передача, вызов инструментов, содержимое рассуждений (цепочка мыслей), развёртывание в нескольких регионах
- **Поддерживаемые регионы**:
  - `beijing` — Северный Китай 2 (Пекин)
  - `virginia` — США (Вирджиния)
  - `singapore` — Сингапур
  - `hongkong` — Гонконг
  - `frankfurt` — Германия (Франкфурт)
- **Поддерживаемые модели** (динамическое обнаружение через API с резервным списком):
  - **Серия Tongyi Qianwen**: qwen3-max, qwen3.6-plus, qwen3.6-flash, qwen-max, qwen-plus, qwen-turbo, qwen3-coder-plus
  - **Рассуждение**: qwq-plus
  - **Сторонние**: deepseek-v3.2, deepseek-r1, glm-5.1, kimi-k2.5, llama-4-maverick
- **Конфигурация**: `apiKey`, `region`, `model`
- **Обнаружение моделей**: получение доступных моделей из API Bailian во время выполнения; откат к кураторскому списку при сетевых сбоях

### VolcengineArkClient (Volcengine Ark)

- **Тип**: облачный AI-сервис
- **Протокол**: API, совместимый с OpenAI
- **Аутентификация**: Bearer token (API-ключ)
- **Функции**: поддержка потокового и непотокового режимов, встроенный двухуровневый контроль скорости
  - Самоконтроль скорости: обеспечение минимального интервала между запросами
  - Серверные ограничения скорости: обработка ошибок 429, повторные попытки с экспоненциальной задержкой
- **Конфигурация**: `apiKey`, `endpoint`, `model`
- **Особенности**: AI-сервис ByteDance, поддержка различных моделей Doubao

### Паттерн фабрики клиентов

Каждый тип AI-клиента имеет соответствующую реализацию фабрики `IAIClientFactory`:

- `OllamaClientFactory` — создаёт экземпляры OllamaClient
- `DashScopeClientFactory` — создаёт экземпляры DashScopeClient
- `VolcengineArkClientFactory` — создаёт экземпляры VolcengineArkClient

Фабрика предоставляет:
- `CreateClient(Dictionary<string, object> config)` — создание экземпляра клиента из конфигурации
- `GetConfigKeyOptions(string key, ...)` — возврат динамических опций для ключа конфигурации (например, доступные модели, регионы)
- `GetDisplayName()` — локализованное отображаемое имя типа клиента

## Ключевые проектные решения

### Хранилище как экземплярный класс (не статический)

`IStorage` спроектирован как внедряемый экземпляр, а не как статическая утилита. Это обеспечивает:

- Прямой доступ к файловой системе — IStorage является внутренним каналом персистентности системы и **не** маршрутизируется через Исполнители.
- **AI не контролирует IStorage** — Исполнители управляют IO, инициированным AI-инструментами; IStorage управляет внутренним чтением/записью данных фреймворка. Это принципиально разные аспекты.
- Возможность тестирования с макетными реализациями.
- Будущую поддержку различных бэкендов хранения без изменения потребителей.

### Исполнители как граница безопасности

Исполнители — **единственный** путь для операций I/O. Инструменты, которым требуется доступ к диску, сети или командной строке, **должны** проходить через Исполнители. Эта архитектура обеспечивает:

- **Отдельный поток планирования** для каждого Исполнителя с блокировкой для проверки разрешений.
- Централизованная проверка разрешений — Исполнитель запрашивает **приватный Менеджер Разрешений** существа.
- Очередь запросов с поддержкой приоритетов и контролем тайм-аута.
- Аудитный журнал всех внешних операций.
- Изоляция исключений — сбой одного Исполнителя не влияет на другие.
- Автоматический Выключатель — последовательные сбои временно останавливают Исполнитель для предотвращения каскадных ошибок.

### ContextManager как лёгкий объект

Каждый вызов `ExecuteOneRound()` создаёт новый экземпляр `ContextManager`:

1. Загружает Файл Души + последнюю историю чата.
2. Отправляет запрос AI-клиенту.
3. Циклически обрабатывает вызовы инструментов, пока AI не вернёт чистый текст.
4. Сохраняет ответ в Систему Чата.
5. Освобождается.

Это сохраняет каждый раунд изолированным и не имеющим состояния.

### Самоэволюция через переопределение классов

Кремниевые Существа могут переписывать свои собственные C#-классы во время выполнения:

1. AI генерирует код нового класса (должен наследовать `SiliconBeingBase`).
2. **Контроль ссылок при компиляции** (основная защита): компилятор получает только разрешённый список сборок — `System.IO`, `System.Reflection` и др. исключены, поэтому опасный код невозможен на уровне типов.
3. **Статический анализ во время выполнения** (вторичная защита): `SecurityScanner` сканирует код на опасные паттерны после успешной компиляции.
4. Roslyn компилирует код в памяти.
5. При успехе: `SiliconBeingManager.ReplaceBeing()` заменяет текущий экземпляр, мигрирует состояние и сохраняет зашифрованный код на диск.
6. При неудаче: новый код отбрасывается, текущая реализация сохраняется.

Пользовательская реализация `IPermissionCallback` также может быть скомпилирована и внедрена через `ReplacePermissionCallback()`, позволяя существам настраивать собственную логику разрешений.

Код хранится на диске в зашифрованном виде с использованием AES-256. Ключ шифрования получается из GUID существа (в верхнем регистре) через PBKDF2.

### Система автоматизации WebView браузера (новое)

Система интегрирует функцию автоматизации WebView браузера на основе **Playwright**:

- **Индивидуальная изоляция**: каждое Кремниевое Существо имеет независимый экземпляр браузера, Cookie и хранилище сессий, полностью изолированные друг от друга.
- **Безголовый режим**: браузер работает в полностью невидимом безголовом режиме, Кремниевые Существа автономно работают в фоновом режиме.
- **WebViewBrowserTool**: предоставляет полные возможности работы с браузером, включая:
  - Навигация по страницам, клики, ввод текста, получение содержимого страницы
  - Выполнение JavaScript, получение скриншотов, ожидание появления элементов
  - Управление состоянием браузера и очистка ресурсов
- **Контроль безопасности**: все операции браузера проходят через цепочку проверки разрешений, предотвращая доступ к вредоносным веб-страницам.

### Сеть Знаний (новое)

Система включает встроенную систему графа знаний на основе **структуры триплетов**:

- **Представление знаний**: структура триплетов «субъект-отношение-объект» (например: Python-is_a-programming_language)
- **KnowledgeTool**: предоставляет полный жизненный цикл управления знаниями:
  - `add`/`query`/`update`/`delete` - базовые операции CRUD
  - `search` - полнотекстовый поиск и сопоставление ключевых слов
  - `get_path` - обнаружение путей связей между двумя концепциями
  - `validate` - проверка полноты знаний
  - `stats` - статистический анализ Сети Знаний
- **Персистентное хранение**: триплеты знаний персистентны в файловой системе, поддержка запросов с временным индексом.
- **Оценка достоверности**: каждая запись знаний имеет оценку достоверности (0-1), поддержка нечёткого сопоставления и сортировки знаний.
- **Классификация по тегам**: поддержка добавления тегов к знаниям для облегчения классификации и поиска.

| `WriteQueue` | Асинхронная Очередь Записи, постановка операций записи в очередь для выполнения в фоновом потоке |
| `FreeList` | Управление свободным пространством, отслеживание повторно используемого пространства в .spk файлах |
| `PackFileReader` | Читатель пакетных файлов, чтение данных из .spk файлов |
| `PackFileWriter` | Записыватель пакетных файлов, запись данных в .spk файлы |
| `SpeedyPackAutoCompactor` | Таймер автоматической компрессии, периодическая компрессия .spk файлов для освобождения свободного пространства |
| `SpeedyPackRegistry` | Процессный менеджер-одиночка, обеспечение использования одного экземпляра SpeedyPack во всём приложении |

### Адаптеры хранения

SiliconLife.Fast интегрирует SpeedyPack в системные интерфейсы через следующие адаптеры:

| Адаптер | Интерфейс | Описание |
|--------|------|------|
| `SpeedyStorage` | `IStorage` | Адаптер хранилища ключ-значение общего назначения |
| `SpeedyTimeStorage` | `ITimeStorage` | Адаптер хранилища с временным индексом |
| `SpeedyWorkNoteStorage` | `IWorkNoteStorage` | Адаптер хранилища рабочих заметок |

### Параметры конфигурации

`SpeedyPackOptions` предоставляет следующие параметры:

| Параметр | Тип | По умолчанию | Описание |
|------|------|--------|------|
| `CacheTtl` | `TimeSpan` | 5 минут | Время жизни записей кэша |
| `MaxCacheEntries` | `int` | 1000 | Максимальное количество записей в кэше |
| `ReadOnly` | `bool` | false | Режим только для чтения |

### Поддержка транзакций

SpeedyPack поддерживает атомарные операции записи через интерфейс `IPackTransaction`:

- `SpeedyTransaction` реализует механизм транзакций
- Поддержка атомарности пакетной записи
- При фиксации транзакции все операции записи либо все успешны, либо все откатываются

## Система плагинов

SiliconLife поддерживает расширение функциональности через систему плагинов, позволяя сторонним разработчикам добавлять новые возможности на платформу.

### Основной интерфейс

```csharp
public interface IPlugin
{
    string Id { get; }
    string GetName(Language language);
    string Version { get; }
    string GetDescription(Language language);
    string GetAuthor(Language language);
    void OnLoad();
    void OnStart();
    void OnStop();
    void OnUnload();
}
```

### Загрузчик Плагинов

`PluginLoader` отвечает за загрузку DLL плагинов из указанного каталога и выполнение строгих проверок безопасности:

1. **Сканирование каталога** — сканирование всех .dll файлов в каталоге плагинов
2. **Проверка безопасности** — проверка ссылок плагина на запрещённые пространства имён
3. **Изолированная загрузка** — использование пользовательского `AssemblyLoadContext` для изолированной загрузки плагина
4. **Управление жизненным циклом** — вызов методов OnLoad, OnStart, OnStop, OnUnload плагина

### Песочница Безопасности

Загрузчик плагинов выполняет следующие проверки безопасности:

| Проверка | Описание |
|--------|------|
| Запрещённые пространства имён | System.IO, System.Net.Http, System.Net.WebSockets, System.Net.Sockets, Microsoft.CodeAnalysis |
| Белый список доверенных сборок | Google.Protobuf, Newtonsoft.Json, MessagePack, Serilog, Microsoft.Extensions.Logging.Abstractions, Dapper |
| Проверка запрещённых типов | Сканирование опасных типов, на которые ссылается плагин |
| Проверка запрещённых членов | Сканирование опасных методов, вызываемых плагином |

### Интеграция инструментов

Плагины могут регистрировать пользовательские инструменты через реализацию интерфейса `ITool`:

- Метод `ToolManager.ScanAllPluginAssemblies()` сканирует все загруженные плагины на наличие реализаций ITool
- Инструменты плагинов автоматически интегрируются в цикл вызова инструментов
- Инструменты плагинов подчиняются той же системе разрешений

### Жизненный цикл плагина

```
Загрузка (OnLoad) → Запуск (OnStart) → Работа → Остановка (OnStop) → Выгрузка (OnUnload)
```

## Активные состояния Кремниевого Существа

Кремниевые Существа имеют следующие активные состояния:

| Состояние | Описание |
|------|------|
| `Idle` | Состояние ожидания, ожидание тактового запуска |
| `SingleChat` | Ведение индивидуального чата |
| `GroupChat` | Ведение группового чата |
| `Task` | Выполнение задачи |
| `Timer` | Выполнение таймера |
| `Stopped` | Остановлено из-за последовательных ошибок или ручной остановки |

**Механизм состояния Stopped**:
- Когда Кремниевое Существо совершает 10 последовательных ошибок, оно автоматически переходит в состояние `Stopped`
- После перехода в состояние Stopped существо больше не выполняет никаких задач
- При поступлении нового чат-сообщения счётчик ошибок сбрасывается, и существо возобновляет работу

Переходы состояний:
```
Idle → SingleChat → Idle (чат завершён)
Idle → GroupChat → Idle (групповой чат завершён)
Idle → Task → Idle (задача завершена)
Idle → Timer → Idle (таймер завершён)
Любое → Stopped (10 последовательных ошибок)
Stopped → Idle (поступление нового чат-сообщения или ручной перезапуск)
```

## Движок рабочих процессов

Движок рабочих процессов — это система конечных автоматов на основе шаблонов, используемая для управления процессами сотрудничества Кремниевых Существ в проектном пространстве:

### Основные компоненты

| Компонент | Описание |
|------|------|
| `WorkflowEngine` | Ядро движка рабочих процессов, управление шаблонами и экземплярами, выполнение переходов состояний на основе Tick |
| `WorkflowTemplate` | Шаблон рабочего процесса, определяющий набор состояний и правила переходов |
| `WorkflowInstance` | Экземпляр рабочего процесса, привязанный к конкретному проекту, отслеживание текущего состояния |
| `WorkflowLog` | Журнал рабочего процесса, запись истории переходов состояний |

### Механизм работы

- **Регистрация шаблонов**: регистрация шаблонов рабочих процессов через `RegisterTemplate()`, определение состояний и правил переходов
- **Создание экземпляров**: создание экземпляров из шаблонов, привязка к проектному пространству
- **Управление на основе Tick**: переходы состояний управляются механизмом Tick Основного Цикла
- **Журналирование**: все переходы состояний автоматически записываются в журнал

## Механизм затухания памяти

`MemoryFadeService` — это служба периодического затухания, моделирующая характеристику забывания биологической памяти:

### Механизм работы

- **Периодическое выполнение**: наследуется от `TickObject`, по умолчанию выполняет цикл затухания каждый час
- **Затухание важности**: применение алгоритма затухания к записям памяти каждого Кремниевого Существа, снижение оценки важности
- **Автоматическая архивация**: автоматическая архивация памяти с важностью ниже порога (`ArchiveFadingMemories()`)
- **Отслеживание статистики**: запись количества циклов затухания, количества записей с изменённым состоянием и другой статистики

### Процесс затухания

```
MemoryFadeService.OnTick()
  └── Перебор всех Кремниевых Существ
       └── being.Memory.ApplyDecay()      # Применение затухания важности
       └── being.Memory.ArchiveFadingMemories()  # Архивация памяти с низкой важностью
```

## Система рабочего пространства проекта

Рабочее пространство проекта — это механизм управления пространством для сотрудничества нескольких Кремниевых Существ:

### Основные функции

- **Жизненный цикл проекта**: создание → активность → архивация → уничтожение
- **Назначение ролей**: поддержка назначения проектных ролей Кремниевым Существам
- **Изоляция разрешений инструментов**: конфигурация разрешений инструментов на уровне проекта, независимая от разрешений уровня Кремниевого Существа
- **Рабочие заметки**: система постраничных заметок в проектном пространстве, поддержка генерации каталогов и поиска по ключевым словам
- **Отслеживание задач**: управление задачами на уровне проекта, поддержка создания, назначения, отслеживания статуса
- **Интеграция рабочих процессов**: проекты могут привязываться к шаблонам рабочих процессов для управления процессами сотрудничества

### Связанные инструменты

| Инструмент | Назначение |
|------|------|
| `ProjectTool` | Управление проектным пространством (создание, архивация, уничтожение, назначение ролей) |
| `ProjectTaskTool` | Управление задачами проекта (создание, назначение, обновление статуса) |
| `ProjectWorkNoteTool` | Рабочие заметки проекта (создание, поиск, генерация каталогов) |
| `ProjectWorkTool` | Рабочие операции проекта (создание задач, групповой чат, широковещание, завершение проекта) |
