## Двойная архитектура версий

Этот проект предлагает две версии реализации, имеющие одинаковую архитектурную концепцию, но различающиеся в хранении и оптимизации производительности:

### SiliconLife.Default (Стандартная версия)
- **Позиционирование**: Стандартная реализация, в основном для проверки архитектурной осуществимости
- **Режим выполнения**: Консольное приложение
- **Метод хранения**: Чистое хранение JSON в файловой системе
- **Применимые сценарии**: Высокие требования к безопасности данных, ограниченные ресурсы памяти, небольшой объём данных
- **Описание роли**: Эталонная реализация для проверки архитектуры, обеспечивает простое и надёжное выполнение, подходит для первого знакомства, отладки разработки или сценариев с приоритетом безопасности данных

### SiliconLife.Fast (Высокопроизводительная версия)
- **Позиционирование**: Основная производственная версия
- **Режим выполнения**: Настольное приложение (Windows/macOS системный трей / Linux окно статуса)
- **Метод хранения**: Хранение в памяти SpeedyPack + асинхронное пакетное сохранение (формат файла .spk)
- **Применимые сценарии**: Высокая параллельность, низкая задержка, большие объёмы данных
- **Поддержка платформ**: Windows/macOS (полный функционал, включая системный трей), Linux (окно статуса, без иконки в трее)
- **Особенности**:
  - Windows/macOS работа в фоновом режиме в системном трее, мониторинг в реальном времени через окно статуса; Linux отображение окна статуса
  - Движок SpeedyPack + автоматическая компрессия гарантируют безопасность данных
  - Архитектура Component UI, 27 декларативных компонентов
  - 7 тем оформления, поддержка автоматического обнаружения и переключения
  - Инструмент горячей перезагрузки для обновлений и перезапусков в режиме онлайн
  - Linux автоматически открывает браузер для доступа к веб-интерфейсу, поддержка параметра `--no-tray`
- **Улучшение производительности**: Задержка чтения снижена в 1000x, задержка записи снижена в 15000x
- **Описание роли**: Готовая к производству реализация с глубокой оптимизацией, с работой в фоновом режиме в системном трее, движком SpeedyPack + автоматической компрессией, лучший выбор для долгосрочной эксплуатации и реальных производственных сред

> **Примечание**: Архитектура, описанная в этом документе, применяется к обеим версиям, различаются только реализации хранения. SiliconLife.Default служит эталоном для проверки архитектуры, SiliconLife.Fast — основная рекомендуемая версия для производства.

## Фундаментальные концепции

### Silicon Being

Каждый ИИ-агент в системе является **Silicon Being** — автономной сущностью с собственной идентичностью, личностью и способностями. Каждый Silicon Being управляется **файлом души** (промпт Markdown), который определяет его модели поведения.

### Silicon Curator

**Silicon Curator** — это специальный Silicon Being с наивысшими системными разрешениями. Он действует как системный администратор:

- Создание и управление другими Silicon Beings
- Анализ пользовательских запросов и декомпозиция на задачи
- Распределение задач соответствующим Silicon Beings
