## Обзор

Web UI предоставляет комплексный интерфейс для управления Кремниевыми Существами, мониторинга состояния системы и взаимодействия с AI-агентами. Система использует чистую серверную архитектуру рендеринга, без зависимостей от фронтенд-фреймворков, генерируя HTML, CSS и JavaScript через построители `H`, `CssBuilder` и `JsBuilder`.

## Доступ

URL по умолчанию: `http://localhost:8080`

## Навигация

### Основные разделы

1. **Панель управления** — обзор системы и метрики
2. **Существа** — управление Кремниевыми Существами
3. **Чат** — взаимодействие с существами (поддержка загрузки файлов, SSE в реальном времени)
4. **История чата** — просмотр истории чатов Кремниевых Существ (список сессий, детали сообщений)
5. **Задачи** — управление задачами (личные задачи)
6. **Таймеры** — конфигурация таймеров (создание, приостановка, история выполнения)
7. **Конфигурация** — системные настройки (AI-клиенты, локализация)
8. **Разрешения** — контроль доступа (управление ACL, запрос разрешений)
9. **Журналы** — системные журналы (фильтрация по уровню, запрос по временному диапазону)
10. **Аудит** — использование токенов и аудитный след
11. **Память** — память существ (временная шкала, расширенная фильтрация)
12. **Знания** — база знаний (управление триплетами, обнаружение путей)
13. **Обозреватель кода** — исследование кода (дерево файлов, подсветка синтаксиса)
14. **Редактор кода** — редактирование кода с всплывающими подсказками (Monaco Editor)
15. **Проекты** — управление проектами (рабочее пространство, задачи, рабочие заметки)
16. **Исполнители** — управление Исполнителями (диск, сеть, командная строка)
17. **Справка** — система справочной документации (многоязычная поддержка, поиск по темам)
18. **О проекте** — системная информация и версия

### Обновления в реальном времени

Использование SSE (Server-Sent Events) для получения данных в реальном времени:

```javascript
const dashboard = new EventSource('/api/dashboard/events');
dashboard.onmessage = (event) => {
    const data = JSON.parse(event.data);
    updateMetrics(data);
};
```

### AI-клиенты

Настройка AI-бэкенда:
- Ollama (локальный)
- Bailian (облачный)
- Volcengine Ark (облачный)
- Herdsman (локальный/облачный, без аутентификации)
- Meituan LongCat (облачный)
- Qiniu Cloud AI (облачный)
- DeepSeek (облачный, режим thinking, 1M контекст)
- Zhipu AI / GLM (облачный, thinking, vision, 1M контекст, бесплатная модель)
- Baidu Qianfan / Ernie (облачный, 131K контекст, бесплатные модели)
- Tencent Hunyuan (облачный, двойной endpoint, 262K контекст)
- MiniMax (облачный, thinking, multimodal M3, 1M контекст)
- Moonshot / Kimi (облачный, thinking, vision, 262K контекст)
- SiliconFlow (облачный, агрегатор 100+ моделей, 1M контекст)
- Пользовательский клиент

Каждый клиентский конфигурационный формуляр динамически предоставляется клиентской фабрикой (API-ключи, эндпоинты, выпадающие списки моделей и т.д.), с соответствующей справочной документацией (прямой переход со страницы конфигурации).

### Платформы мгновенных сообщений (мультиинстанс)

Конфигурация платформ мгновенных сообщений поддерживает мультиинстансную архитектуру — можно одновременно включать несколько платформ:

1. Нажмите **Добавить платформу** и выберите тип платформы:
   - **Web UI** (встроенная, включена по умолчанию)
   - **Feishu** (поддерживает ручную настройку и OAuth-авторизацию одним щелчком)
   - **WeCom** (ручная настройка)
   - **DingTalk** (ручная настройка, поддержка режимов Stream / HTTP для событий)
2. Заполните поля платформы в динамическом формуляре (обязательные поля отмечены звёздочкой, ключевые поля — поля пароля)
3. Каждый экземпляр можно независимо включать/отключать и удалять

**Подстановочные знаки переменных окружения**: значения конфигурации поддерживают `${ENV_VAR}` (например, `"${FEISHU_APP_SECRET}"`), разрешается из переменных окружения во время выполнения, открытые ключи не записываются в config.json.

**Мастер OAuth-авторизации** (Feishu): после сохранения appId/appSecret на странице конфигурации появляется встроенная область авторизации; нажмите кнопку **Авторизовать** — откроется системный браузер с переходом на страницу авторизации Feishu; после завершения авторизации токен автоматически записывается в конфигурацию, страница отображает статус авторизации в реальном времени через SSE (успех/сбой/тайм-аут), без ручного копирования и вставки.

### MCP-серверы

Список MCP-серверов централизованно управляется на странице конфигурации (редактор массивов): по одной строке на сервер (ID, имя, способ передачи stdio/http, команда или эндпоинт, состояние включения), с возможностью **добавления** и **удаления** в строке. После сохранения сервер немедленно подключается, его инструменты автоматически внедряются в Кремниевые Существа. Подробнее см. раздел [Управление MCP](#управление-mcp) ниже.

### Настройки хранения

- Версия Default: базовый путь, временной индекс, политика очистки
- Версия Fast: конфигурация движка хранения SpeedyPack, управление файлами .spk, настройки автоматической компрессии

## Система тем

### Доступные темы

1. **Admin** — профессиональный административный интерфейс
2. **Chat** — дизайн, центрированный на диалогах
3. **Creative** — творческий и художественный стиль
4. **Dev** — макет, ориентированный на разработчиков
5. **HighContrast** — тема высокой контрастности (версия Fast)
6. **Minimal** — минималистичный стиль (версия Fast)
7. **Light** — светлая тема (версия Fast)

### Переключение тем

1. Нажмите **Настройки** (иконка шестерёнки)
2. Выберите **Тема**
3. Выберите нужную тему
4. Интерфейс обновится немедленно

### Пользовательская тема

Создание пользовательской темы через реализацию `ISkin`:

```csharp
public class MySkin : ISkin
{
    public string Name => "MySkin";
    
    public string GetCss()
    {
        return ":root { --primary: #color; }";
    }
}
```

## Управление разрешениями

### Просмотр разрешений

- Список всех правил разрешений
- Фильтрация по пользователю или ресурсу
- Просмотр дат истечения

### Добавление правила разрешений

1. Нажмите **Добавить правило**
2. Настройте:
   - Тип разрешения (например, `FileAccess`, `NetworkAccess`)
   - Префикс ресурса (например, `C:\Projects`, `api.github.com`)
   - Разрешить/Отказать
   - Описание
3. Сохраните

### Аудитный след

Просмотр всех решений о разрешениях:
- Метка времени
- Пользователь
- Ресурс
- Решение
- Причина

### Управление разрешениями инструментов

Управление разрешениями операций инструментов для Кремниевых Существ и проектов:

1. **Разрешения инструментов Кремниевого Существа**:
   - Перейдите в **Существа** → выберите существо → **Разрешения инструментов**
   - Просмотр текущей конфигурации разрешений
   - Установка разрешения/отказа для каждой операции
   - Применение шаблона разрешений (readonly/restricted/full)

2. **Разрешения инструментов проекта**:
   - Перейдите в **Проекты** → выберите проект → **Разрешения инструментов**
   - Разрешения инструментов на уровне проекта независимы от уровня Кремниевого Существа
   - Реализация изоляции разрешений между проектами

## Загрузка файлов

### Функции

- Диалог выбора источника файлов
- Поддержка загрузки нескольких файлов
- Управление метаданными файлов
- Отображение прогресса загрузки

### Использование загрузки файлов

1. В интерфейсе чата нажмите кнопку **Загрузить файл**
2. Откроется диалог выбора источника файлов
3. Выберите источник файлов:
   - Локальный файл
   - Путь файловой системы
4. Выберите файлы (поддерживается множественный выбор)
5. Подтвердите загрузку
6. Информация о файле будет прикреплена к сообщению

### Поддерживаемые типы файлов

- Текстовые файлы (.txt, .md, .json, .xml и др.)
- Файлы кода (.cs, .js, .py, .java и др.)
- Файлы конфигурации (.yml, .yaml, .ini, .conf и др.)
- Файлы документов (.csv, .log и др.)

## Система справочной документации (новое)

### Обзор функций

Система справочной документации предоставляет многоязычную поддержку справочной документации для Кремниевых Существ и пользователей.

### Использование справочной документации

1. Перейдите на страницу **Справка**
2. Просмотрите список тем справки:
   - Руководство быстрого старта
   - Справочник использования инструментов
   - Руководство по управлению разрешениями
   - Руководство по устранению неполадок
   - Руководство разработчика
3. Нажмите на тему для просмотра подробного содержания:
   - Структурированное содержание документации (рендеринг Markdown)
   - Многоязычная поддержка (следует системным настройкам локализации)
   - Рекомендации связанных тем
4. Используйте функцию поиска для быстрого нахождения:
   - Поиск по ключевым словам (поддержка китайского, английского)
   - Результаты поиска отсортированы по релевантности

### Доступ Кремниевых Существ к справке

Кремниевые Существа могут обращаться к справочной документации через инструмент `help`:
```json
{
  "action": "get_topics"
}
```

### Техническая реализация

- **Контроллер**: `HelpController`
- **Инструмент**: `HelpTool`
- **API-маршруты**:
  - `/api/help` — получение списка тем справки
  - `/api/help/{topicId}` — получение деталей темы
  - `/api/help/search?q=keyword` — поиск справочной документации

## Рабочее пространство проекта (новое)

### Обзор функций

Рабочее пространство проекта предоставляет структурированную рабочую среду с поддержкой управления проектами, отслеживания задач и рабочих заметок.

### Управление проектами

1. **Создание проекта**:
   - Название и описание проекта
   - Теги проекта (категоризация)
   - Статус проекта (в процессе, завершён, архивирован)
2. **Просмотр деталей проекта**:
   - Основная информация о проекте
   - Связанный список задач
   - Список рабочих заметок
   - Статистика прогресса проекта
3. **Архивация проекта**: сохранение исторических данных без активного использования
4. **Управление ролями проекта**:
   - Назначение проектных ролей Кремниевым Существам (например, developer, reviewer, manager)
   - Удаление назначений ролей
   - Просмотр участников проекта и списка ролей
5. **Рабочие процессы проекта**:
   - Просмотр списка шаблонов рабочих процессов
   - Привязка шаблона рабочего процесса к проекту
   - Просмотр состояния экземпляра рабочего процесса
   - Просмотр журнала выполнения рабочего процесса

### Рабочие заметки (приватные)

Личные рабочие заметки Кремниевого Существа, аналогичные дневнику:

1. **Создание заметки**:
   - Резюме (краткое описание)
   - Содержание (поддержка формата Markdown)
   - Ключевые слова (для поиска)
   - Автоматическая запись метки времени
2. **Управление заметками**:
   - Просмотр по временной шкале (постраничный дизайн)
   - Поиск заметок (по ключевым словам, резюме, содержанию)
   - Генерация каталога (быстрый просмотр структуры заметок)
   - Обновление и удаление заметок
3. **Контроль разрешений**:
   - По умолчанию приватные, доступны только самому существу
   - Кремниевый Куратор может управлять всеми заметками

### Техническая реализация

- **Контроллер**: `WorkNoteController`
- **Инструменты**: `WorkNoteTool`, `ProjectTool`, `ProjectWorkNoteTool`
- **API-маршруты**:
  - `/api/worknotes` — получение списка рабочих заметок
  - `/api/worknotes/{id}` — получение деталей заметки
  - `/api/worknotes/search?q=keyword` — поиск заметок
  - `/api/worknotes/directory` — генерация каталога заметок
  - `/api/projects` — API управления проектами

## Управление навыками

### Обзор функций

Навык (Skill) — это переиспользуемая единица возможностей «оркестрация инструментов + шаблон промпта». Страница управления навыками (`/skill?beingId={id}`) предоставляет визуальное управление навыками для каждого Кремниевого Существа.

### Макет страницы

- **Список навыков слева**: карточный показ (заголовок, бейджи `версия · источник · режим запуска`, описание)
- **Редактор справа**: Markdown-редактор (метаданные YAML front matter + текст промпта)
- **Статистика сверху**: общее число навыков / число пользовательских навыков / квота (например, `5 / 2 / 50`)

### Операции на панели инструментов

- **Создать**: загрузить шаблон Markdown-навыка
- **Импорт .md / Импорт .json**: импорт навыка из локального файла
- **Обновить**: перезагрузить список навыков

### Операции с карточкой навыка

Каждая карточка навыка предоставляет 5 операций:

| Операция | Описание |
|----------|----------|
| Редактировать | Открыть Markdown в правом редакторе, можно сохранить (upsert) |
| Тестировать | Ввести JSON параметров, немедленно выполнить навык и просмотреть результат |
| Экспорт JSON | Скачать `{id}.json` |
| Экспорт Markdown | Скачать `{id}.md` |
| Удалить | Удалить навык (включая персистентный файл) |

### Написание навыка

Навыки пишутся на Markdown: метаданные YAML front matter объявляют id, описание, схему параметров, белый список инструментов, режим запуска и т.д.; текст — шаблон промпта (поддерживает заполнители `{param}`). Можно написать только текст (опустить YAML) — при сохранении AI автоматически дополнит недостающие метаданные, при этом поля, предоставленные пользователем, никогда не перезаписываются.

```markdown
---
id: daily_news_digest
description: Поиск сегодняшних технических новостей и генерация сводки
tool_whitelist: [network, work_note]
trigger_mode: Auto
metadata:
  schedule: "0 9 * * *"
---

Используйте инструмент network для поиска последних новостей по теме {topic}, сгенерируйте сводку на 500 слов и сохраните в рабочие заметки.
```

### Техническая реализация

- **Контроллер**: `SkillController` (страница + 10 API-эндпоинтов)
- **Ядро**: `SkillManager` (регистрация/выполнение/горячая перезагрузка), `SkillMetadataCompleter` (AI-дополнение метаданных)
- **Горячая перезагрузка**: существо проверяет изменения в каталоге `skills/` каждые 30 секунд, после сохранения в Web UI перезапуск не требуется
- **Архивация версий**: каждое обновление автоматически архивируется в `skills/archive/{id}/{version}.md`

## Управление MCP

### Обзор функций

Страница управления MCP (Model Context Protocol, протокол контекста модели) (`/mcp`) предназначена для управления подключениями внешних MCP-серверов. После подключения инструменты, предоставляемые сервером, автоматически внедряются во все Кремниевые Существа в формате `mcp_{ID_сервера}_{имя_инструмента}`.

### Список серверов

Для каждого сервера отображается: ID, имя, способ передачи (stdio/http), статус подключения (connected/disconnected/connecting/error), состояние включения, количество инструментов, последняя ошибка.

### Управляющие операции

| Операция | Описание |
|----------|----------|
| Добавить сервер | Заполнить ID (строчные буквы/цифры/подчёркивания), имя, способ передачи; для stdio требуется команда и аргументы, для http — URL эндпоинта |
| Включить/Отключить | Переключатель в строке, после отключения инструменты отменяются для всех существ |
| Переподключить | Отключить и переподключить, обновить список инструментов |
| Удалить | Удалить конфигурацию сервера и все его инструменты |
| Просмотр инструментов | Развернуть сервер, показать имена инструментов (с префиксом), описание, схему параметров |
| Тест инструмента | Непосредственно вызвать MCP-инструмент для проверки связи (без участия AI) |

### Пример добавления stdio-сервера

```json
{
  "id": "filesystem",
  "name": "Filesystem",
  "transport": "stdio",
  "command": "npx",
  "arguments": ["-y", "@modelcontextprotocol/server-filesystem", "/data"],
  "enabled": true
}
```

### Механизм безопасности

- Добавление/удаление/запуск/остановка серверов выполняется только пользователем через Web UI; AI не может изменять список серверов (инструмент `mcp` предоставляет только запросы на чтение)
- Обёрнутые MCP-инструменты представлены в матрице разрешений инструментов единым действием `execute`, могут быть отключены индивидуально по существу/проекту
- Глобальный переключатель `McpEnabled` может мгновенно отключить всю MCP-интеграцию

## Устранение неполадок

### Невозможно подключиться

**Проверьте**:
- Сервер запущен
- Порт 8080 не заблокирован
- Настройки брандмауэра

### SSE не работает

**Проверьте**:
- Браузер поддерживает SSE
- Нет прокси-буферизации SSE
- Стабильность сети

### Медленная производительность

**Оптимизация**:
- Снижение уровня детализации журналов
- Очистка старых данных аудита
- Проверка системных ресурсов
