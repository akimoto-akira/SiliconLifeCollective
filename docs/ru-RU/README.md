# Silicon Life Collective

**Версия: v0.2.0-alpha** | **Silicon Life Collective** — Платформа многоагентного взаимодействия на основе .NET 9, где ИИ-агенты называются **Silicon Beings** и могут самостоятельно развиваться благодаря динамической компиляции Roslyn.

## 🌟 Ключевые возможности

### Система агентов
- **Многоагентная оркестрация** — Централизованное управление через *Silicon Curator* с механизмом справедливого планирования по временным квантам
- **Управление файлом души** — Каждый Silicon Being управляется центральным файлом промпта (`soul.md`), определяющим уникальную личность и модели поведения
- **Архитектура Body-Brain** — *Body* (SiliconBeing) получает сигналы жизнедеятельности и обнаруживает сценарии срабатывания; *Brain* (ContextManager) отвечает за загрузку истории, вызовы ИИ, выполнение инструментов и сохранение ответов
- **Способность к саморазвитию** — Благодаря технологии динамической компиляции Roslyn, Silicon Beings могут переписывать собственный код для реализации эволюции
- **Управление состояниями активности** — Поддержка четырёх состояний: Idle (простой), Working (работа), Error (ошибка), Stopped (остановлен). Автоматический переход в Stopped после 10 последовательных ошибок

### Система плагинов
- **Архитектура расширения через плагины** — Расширение функциональности через интерфейс IPlugin, поддержка динамической загрузки DLL плагинов из каталога
- **Безопасная песочница** — Загрузчик плагинов проводит строгий анализ безопасности, запрещает доступ к System.IO, System.Net и другим пространствам имён
- **Изолированная загрузка** — Использование пользовательского AssemblyLoadContext для изолированной загрузки, предотвращение влияния плагинов на стабильность основной программы
- **Интеграция инструментов** — Плагины могут регистрировать пользовательские инструменты через интерфейс ITool, автоматически интегрируемые в цикл вызова инструментов

### Инструменты и выполнение
- **24 встроенных инструмента** — Покрытие календаря, чата, конфигурации, диска, сети, памяти, задач, таймеров, базы знаний, рабочих заметок, браузера WebView, горячей перезагрузки и др.
- **Инструмент горячей перезагрузки** — Поддержка автоматической компиляции, обновления файлов и перезапуска SiliconLife.Fast во время работы без ручного вмешательства
- **Цикл вызова инструментов** — ИИ возвращает вызов инструмента → Выполнить инструмент → Вернуть результаты ИИ → Продолжить цикл до получения текстового ответа
- **Безопасность разрешений исполнителя** — Все операции ввода-вывода проходят строгую проверку разрешений через исполнителей
  - Цепочка разрешений из 5 уровней: UserFrequencyCache → IPermissionCallback → (Куратор→IPermissionAskHandler / НеКуратор→GlobalACL→Deny)
  - Полный аудит-лог всех решений о разрешениях

### ИИ и знания
- **Поддержка нескольких ИИ-бэкендов**
  - **Ollama** — Локальное развёртывание моделей, с нативным HTTP API
  - **Alibaba Cloud DashScope (Bailian)** — Облачный ИИ-сервис, совместимый с OpenAI API, поддержка 13+ моделей, многорегиональное развёртывание
  - **Volcengine Ark (VolcengineArk)** — Облачный ИИ-сервис ByteDance, поддержка потокового и непотокового режимов, встроенный контроль скорости
- **32 системы календаря** — Полное покрытие основных мировых календарей, включая григорианский, китайский лунный, исламский, еврейский, японский, персидский, майя, китайский исторический и др.
- **Система сети знаний** — Граф знаний на основе триплетов (субъект-отношение-объект), поддержка хранения, запросов и поиска путей

### Веб-интерфейс
- **Современный веб-интерфейс** — Встроенный HTTP-сервер с обновлениями в реальном времени через SSE
- **7 тем оформления** — Версии Admin, Chat, Creative, Dev, Высокая контрастность, Light, Minimal, поддержка автоматического обнаружения и переключения
- **23 контроллера** — Полное управление системой, чат, конфигурация, функции мониторинга
- **Нулевая зависимость от фронтенд-фреймворков** — HTML/CSS/JS генерируются на стороне сервера через `H`, `CssBuilder` и `JsBuilder`

### Данные и хранение
- **Высокопроизводительное хранилище SpeedyPack** — Версия Fast использует собственный движок хранения .spk, отображение каталогов в памяти + кэш записей + очередь асинхронной записи
- **Хранение в файловой системе** — Версия Default использует чистое хранение JSON в файловой системе
- **Запросы по временному индексу** — Эффективные запросы по диапазону времени через интерфейс `ITimeStorage`
- **Автоматическая компрессия** — SpeedyPack поддерживает автоматическую компрессию по расписанию для освобождения пространства хранения
- **Минимальные зависимости** — Основная библиотека зависит только от Microsoft.CodeAnalysis.CSharp для динамической компиляции

## 🔄 Двойная архитектура версий

Этот проект предлагает две версии реализации для различных сценариев:

### SiliconLife.Default (Стандартная версия)
- **Позиционирование**: Стандартная реализация, в основном для проверки архитектурной осуществимости
- **Режим выполнения**: Консольное приложение
- **Метод хранения**: Чистое хранение JSON в файловой системе
- **Применимые сценарии**: Высокие требования к безопасности данных, ограниченные ресурсы памяти, небольшой объём данных
- **Особенности**: Простота и надёжность, немедленное сохранение данных, отсутствие риска потери данных
- **Описание роли**: Эталонная реализация для проверки архитектуры, подходит для первого знакомства, отладки разработки или сценариев с приоритетом безопасности данных
- **Команда запуска**: `dotnet run --project src/SiliconLife.Default`

### SiliconLife.Fast (Высокопроизводительная версия)
- **Позиционирование**: Основная производственная версия
- **Режим выполнения**: Настольное приложение (Windows/macOS системный трей / Linux окно статуса)
- **Метод хранения**: Хранение в памяти SpeedyPack + асинхронное пакетное сохранение (формат файла .spk)
- **Применимые сценарии**: Высокая параллельность, низкая задержка, большие объёмы данных
- **Поддержка платформ**: Windows/macOS (полный функционал, включая системный трей), Linux (окно статуса, без иконки в трее)
- **Особенности**:
  - Экстремальная оптимизация производительности
  - Windows/macOS работа в фоновом режиме в системном трее с мониторингом в реальном времени; Linux отображение окна статуса
  - Движок SpeedyPack + автоматическая компрессия гарантируют безопасность данных
  - Архитектура Component UI, 27 декларативных компонентов
  - 7 тем оформления, поддержка автоматического обнаружения и переключения
  - Инструмент горячей перезагрузки для обновлений и перезапусков в режиме онлайн
- **Улучшение производительности**: Задержка чтения из памяти снижена в 1000x, задержка записи снижена в 15000x, параллельная обработка увеличена в 50x
- **Описание роли**: Готовая к производству реализация с глубокой оптимизацией, лучший выбор для долгосрочной эксплуатации и реальных производственных сред
- **Команда запуска**: `dotnet run --project src/SiliconLife.Fast`

### Сравнение версий

| Характеристика | SiliconLife.Default | SiliconLife.Fast |
|---------|---------------------|------------------|
| **Режим выполнения** | Консольное приложение | Настольное приложение (Windows/macOS системный трей / Linux окно статуса) |
| **Пользовательский интерфейс** | Веб-интерфейс (доступ через браузер) | Windows/macOS: Иконка в трее + Окно статуса + Веб-интерфейс; Linux: Окно статуса + Веб-интерфейс |
| **Системный трей** | ❌ Нет | ✅ Windows/macOS поддерживает сворачивание в трей; Linux без иконки в трее |
| **Фоновая работа** | ❌ Завершается при закрытии консоли | ✅ Windows/macOS непрерывная работа в трее; Linux работа в окне статуса |
| **Метод хранения** | Хранение JSON в файловой системе | Хранение в памяти SpeedyPack + асинхронное сохранение |
| **Движок хранения** | Файловый ввод-вывод | SiliconLife.Speedy (формат .spk) |
| **Задержка чтения** | ~10мс (дисковый ввод-вывод) | ~0.01мс (операция в памяти) |
| **Задержка записи** | ~15мс (синхронная запись) | ~0.001мс (асинхронная запись) |
| **Параллельность** | ~100 запросов/с | ~5000 запросов/с |
| **Использование памяти** | ~200МБ | ~500МБ |
| **Безопасность данных** | Очень высокая (немедленное сохранение) | Высокая (асинхронное сохранение + автоматическая компрессия) |
| **Применимые сценарии** | Приоритет безопасности данных, небольшие данные | Приоритет производительности, большие данные, высокая параллельность |
