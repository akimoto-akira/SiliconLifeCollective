# Справочник инструментов

> **Версия: v0.2.0-alpha**

Этот документ подробно описывает все встроенные инструменты платформы Silicon Life Collective.

[English](../en/tools-reference.md) | [Deutsch](../de-DE/tools-reference.md) | [中文](../zh-CN/tools-reference.md) | [繁體中文](../zh-HK/tools-reference.md) | [Español](../es-ES/tools-reference.md) | [日本語](../ja-JP/tools-reference.md) | [한국어](../ko-KR/tools-reference.md) | [Čeština](../cs-CZ/tools-reference.md) | **Русский**

## Обзор

Система инструментов позволяет Кремниевым Существам взаимодействовать с внешним миром через стандартизированный интерфейс. Каждый инструмент реализует интерфейс `ITool` и автоматически обнаруживается и регистрируется `ToolManager` через рефлексию.

### Классификация инструментов

- **Инструменты системного управления** — конфигурация, разрешения, динамическая компиляция, управление Куратором
- **Инструменты коммуникации** — чат, сетевые запросы
- **Инструменты хранения данных** — дисковые операции, база данных, память, рабочие заметки
- **Инструменты управления временем** — календарь, таймеры, задачи
- **Инструменты разработки** — выполнение кода, запросы журналов
- **Утилиты** — системная информация, аудит токенов, справочная документация, Сеть Знаний
- **Инструменты браузера** — автоматизация WebView браузера
- **Инструменты проекта** — управление проектами, задачи проекта, рабочие заметки проекта, работа проекта
- **Инструменты расширения** — инструменты внешних серверов MCP, управление навыками
- **Инструменты плагинов** — сторонние инструменты, зарегистрированные через систему плагинов

### Система сценариев инструментов

Каждый инструмент объявляет свои доступные сценарии через атрибут `[ToolScenario]`:

| Флаг сценария | Значение | Описание |
|----------|------|-------------|
| `Chat` | `1 << 0` | Сценарий чата (пользователь общается с Кремниевым Существом) |
| `Task` | `1 << 1` | Сценарий задачи (Кремниевое Существо выполняет задачу) |
| `Timer` | `1 << 2` | Сценарий таймера (Кремниевое Существо выполняет задание по таймеру) |
| `MemoryCompression` | `1 << 3` | Сценарий сжатия памяти |
| `Project` | `1 << 4` | Сценарий проекта (режим ThinkOnProject) |
| `All` | Все вышеперечисленные | Доступно во всех сценариях |

Кроме того, инструменты, помеченные атрибутом `[ChatOnly]`, доступны только в сценарии чата (например, HelpTool) и не появляются в сценариях задач и таймеров.

## Список встроенных инструментов

### 1. Инструмент Календаря (CalendarTool)

**Имя инструмента**: `calendar`

**Описание**: поддержка преобразования и вычисления дат в 32 календарных системах.

**Поддерживаемые операции**:
- `now` — получить текущее время
- `format` — форматировать дату
- `add_days` — добавить/вычесть дни
- `diff` — вычислить разницу дат
- `list_calendars` — перечислить все поддерживаемые календари
- `get_components` — получить компоненты даты
- `get_now_components` — получить компоненты текущего времени
- `convert` — преобразование между календарными системами

**Поддерживаемые календарные системы** (32):
- Григорианский (Gregorian)
- Китайский лунный (Chinese Lunar)
- Китайский исторический (Chinese Historical) — летоисчисление гань-чжи, императорские эры
- Исламский (Islamic)
- Еврейский (Hebrew)
- Японский (Japanese)
- Персидский (Persian)
- Майя (Mayan)
- Буддийский (Buddhist)
- Тибетский (Tibetan)
- и 24 других календаря...

**Пример использования**:
```json
{
  "action": "convert",
  "date": "2026-04-26",
  "from_calendar": "gregorian",
  "to_calendar": "chinese_lunar"
}
```

### 11. Инструмент Запроса MCP (McpTool)

**Имя инструмента**: `mcp`

**Описание**: запрос состояния интеграции MCP (Model Context Protocol) — подключённые внешние серверы, предоставляемые ими инструменты и способы их вызова. Это инструмент только для чтения: добавление/удаление серверов может выполнять только пользователь через Web UI, AI не может изменять список серверов.

**Поддерживаемые операции**:
- `status` — глобальный обзор (состояние включения, количество серверов, количество инструментов)
- `list_servers` — перечислить настроенные серверы (со статусом подключения и количеством инструментов)
- `list_tools` — перечислить доступные инструменты (имена с префиксом `mcp_{server}_{tool}`, описания и schema параметров; опциональный `server_id` для фильтрации по отдельному серверу)

**Пример использования**:
```json
{
  "action": "list_tools",
  "server_id": "filesystem",
  "include_schema": true
}
```

**Инструменты-обёртки MCP**: инструменты каждого подключённого сервера MCP динамически регистрируются у Кремниевого Существа как отдельные инструменты с именами формата `mcp_{serverId}_{toolName}` (например, `mcp_filesystem_read_file`). AI может вызывать их напрямую по имени с префиксом, как обычные инструменты, без обращения к этому инструменту запроса. Инструменты-обёртки представлены в матрице разрешений единым действием `execute` и могут быть отключены по отдельности.

**Сценарии**: все сценарии (`All`)

### 16. Инструмент Проекта (ProjectTool) 🔒

- `remove_role` — удалить проектную роль Кремниевого Существа
- `list_roles` — перечислить назначения ролей проекта

**Пример использования**:

### 18. Инструмент Рабочих Заметок Проекта (ProjectWorkNoteTool)

**Имя инструмента**: `project_work_note`

**Доступные сценарии**: Chat, Task, Timer

**Описание**: управление рабочими заметками в проектном пространстве (общедоступными, аналогично рабочей тетради), поддержка постраничного управления заметками.

**Поддерживаемые операции**:
- `create` — создать страницу заметки (требуются `project_id`, `summary` и `content`, опционально `keywords`)
- `read` — прочитать страницу заметки (требуются `project_id` и `page_number` или `note_id`)
- `update` — обновить страницу заметки (требуются `project_id`, `page_number` и `content`, опционально `summary` и `keywords`)
- `delete` — удалить страницу заметки (требуются `project_id` и `page_number` или `note_id`)
- `list` — перечислить сводки всех страниц заметок проекта
- `directory` — сгенерировать каталог/обзор заметок
- `search` — поиск заметок по ключевым словам (требуются `project_id` и `keyword`, опционально `max_results`)

**Пример использования**:
```json
{
  "action": "create",
  "project_id": "project-uuid",
  "summary": "Завершён модуль аутентификации пользователей",
  "content": "## Детали реализации\n\n- Использование JWT token",
  "keywords": "аутентификация,JWT"
}
```

- `broadcast` — транслировать сообщение в канал проекта
- `complete` — отметить проект как завершённый
- `status` — получить статус проекта

**Пример использования**:
```json
{
```

### 20. Инструмент Навыков (SkillTool)

**Имя инструмента**: `skill`

**Описание**: управление навыками Кремниевого Существа (многоразовыми единицами возможностей «оркестрация инструментов + шаблон промпта»), поддержка создания, перечисления, обновления, удаления, импорта и экспорта. Отсутствующие метаданные (id, описание, schema параметров и т. д.) автоматически дополняются AI.

**Поддерживаемые операции**:
- `create` — создать новый навык (требуются `id` и `system_prompt`, опционально `description`, `parameter_schema`, `tool_whitelist`, `tags`, `max_tool_round`, `timeout`, `on_complete`, `trigger_mode`, `auto_trigger_condition`)
- `list` — перечислить все доступные навыки (со сводками)
- `update` — обновить существующий навык через параметры (требуется `skill_id`)
- `update_from_md` — обновить навык из строки Markdown (метаданные YAML front matter + текст промпта)
- `delete` — удалить навык (требуется `skill_id`)
- `export` — экспортировать навык в JSON (требуется `skill_id`)
- `export_md` — экспортировать навык в Markdown (требуется `skill_id`)
- `import` — импортировать навык из JSON (требуется `json`)
- `import_md` — импортировать навык из Markdown (требуется `markdown`)

**Пример использования**:
```json
{
  "action": "create",
  "id": "daily_news_digest",
  "description": "Поиск сегодняшних технологических новостей и создание сводки",
  "system_prompt": "Используй инструмент network для поиска последних новостей по теме {topic} и сгенерируй сводку на 500 слов.",
  "parameter_schema": {
    "type": "object",
    "properties": {
      "topic": { "type": "string", "description": "Тема новостей" }
    },
    "required": ["topic"]
  },
  "tool_whitelist": ["network", "work_note"],
  "trigger_mode": "Auto",
  "auto_trigger_condition": "schedule",
  "metadata": { "schedule": "0 9 * * *" }
}
```

**Права на изменение**: Куратор может изменять все навыки; обычные Существа могут изменять только навыки с источником `Being` или `User` (встроенные навыки и навыки плагинов изменять нельзя).

**Ограничение количества**: количество пользовательских навыков каждого Существа ограничено конфигурацией `MaxCustomSkillsPerBeing` (по умолчанию 50).

**Сценарии**: все сценарии (`All`)

> Полное описание системы навыков (режимы запуска, белый список, горячая перезагрузка, автоматическое планирование и т. д.) см. [Руководство Кремниевого Существа](silicon-being-guide.md#система-навыков).

## Процесс вызова инструментов

```
┌──────────┐
│   AI     │ Возвращает tool_calls
└────┬─────┘
     ↓
┌──────────────┐
│ ToolManager  │ Поиск и проверка прав использования инструмента
└────┬─────────┘
     ↓
┌──────────────┐
│ Permission   │ Проверка цепочки разрешений
│   Manager    │
└────┬─────────┘
     ↓
┌──────────────┐
│  Executor    │ Выполнение операций доступа к ресурсам
└────┬─────────┘
     ↓
┌──────────┐
│   AI     │ Получение результата инструмента, продолжение размышлений
└──────────┘
```

## Проверка разрешений

Все выполнения инструментов проходят через цепочку проверки разрешений:

1. **UserFrequencyCache** — кэш высокочастотных пользовательских решений (HighDeny имеет приоритет над HighAllow)
2. **IPermissionCallback** — пользовательская функция обратного вызова разрешений (Allowed/Denied/AskUser)
3. **Ветвление IsCurator** — Куратор запрашивает пользователя через IPermissionAskHandler; не-Куратор проверяет GlobalACL, при отсутствии подходящего правила — отказ по умолчанию

## Создание пользовательского инструмента

### Шаг 1: Реализация интерфейса ITool

```csharp
public class MyCustomTool : ITool
{
    public string Name => "my_tool";
    
    public string Description => "Описание инструмента";
    
    public ToolDefinition Definition => new ToolDefinition
    {
        Name = Name,
        Description = Description,
        Parameters = new Dictionary<string, object>
        {
            ["param1"] = new { type = "string", description = "Описание параметра" }
        }
    };
    
    public async Task<ToolResult> ExecuteAsync(ToolCall call)
    {
        try
        {
            var param1 = call.Parameters["param1"]?.ToString();
            var result = await DoWork(param1);
            
            return new ToolResult
            {
                Success = true,
                Output = result
            };
        }
        catch (Exception ex)
        {
            return new ToolResult
            {
                Success = false,
                Error = ex.Message
            };
        }
    }
}
```

### Шаг 2: Добавление в проект

Поместите файл инструмента в каталог `src/SiliconLife.Common/Tools/` (общие инструменты) или в каталог `src/SiliconLife.Default/Tools/` / `src/SiliconLife.Fast/Tools/` (версионно-специфичные инструменты). `ToolManager` автоматически обнаружит и зарегистрирует его через рефлексию при запуске.

### Шаг 2a: Регистрация инструмента через плагин

Также можно зарегистрировать пользовательский инструмент через систему плагинов:

1. Реализуйте интерфейс `ITool` в проекте плагина
2. Скомпилируйте DLL плагина и поместите в каталог плагинов
3. `ToolManager.ScanAllPluginAssemblies()` автоматически просканирует все загруженные плагины на наличие реализаций ITool
4. Инструменты плагинов подчиняются той же системе разрешений

### Шаг 3: (Опционально) Пометка как доступный только для Куратора

```csharp
[SiliconManagerOnly]
public class AdminOnlyTool : ITool
{
    // Доступно только Куратору
}
```

### Альтернативы: навыки и инструменты MCP

Помимо написания классов инструментов на C#, существуют два способа расширения, не требующие компиляции:

- **Навык (Skill)**: создание комбинаций «оркестрация инструментов + шаблон промпта» через Web UI или инструмент `skill`; подходит для инкапсуляции часто используемых рабочих процессов в многократно используемые возможности. См. [Руководство Кремниевого Существа — Система навыков](silicon-being-guide.md#система-навыков).
- **Серверы MCP**: после настройки внешнего MCP-сервера в Web UI его инструменты автоматически внедряются в формате `mcp_{serverId}_{toolName}`, без написания какого-либо кода. См. [Руководство по Web UI — Управление MCP](web-ui-guide.md).

## Лучшие практики

### 1. Всегда валидируйте параметры

```csharp
if (!call.Parameters.ContainsKey("required_param"))
{
    return ToolResult.Failure("Отсутствует обязательный параметр: required_param");
}
```

### 2. Корректно обрабатывайте ошибки

```csharp
try
{
    // Выполнение операции
}
catch (Exception ex)
{
    Logger.Error($"Инструмент {Name} не удалось выполнить: {ex.Message}");
    return ToolResult.Failure(ex.Message);
}
```

### 3. Уважайте систему разрешений

Никогда не обходите проверки разрешений. Всегда обращайтесь к ресурсам через Исполнители:

```csharp
bool allowed = permissionManager.CheckPermission(callerId, permissionType, resource);
if (!allowed)
{
    return ToolResult.Denied("Permission denied");
}
```

### 4. Предоставляйте чёткие описания инструментов

Помогайте AI понять, когда и как использовать инструмент:

```csharp
public string Description => 
    "Используется для преобразования дат между различными календарными системами." +
    "Необходимо предоставить параметры 'date', 'from_calendar' и 'to_calendar'.";
```

## Устранение неполадок

### Инструмент не найден

**Проблема**: AI пытается вызвать несуществующий инструмент.

**Решение**:
- Проверьте, что имя инструмента точно совпадает
- Убедитесь, что файл инструмента находится в каталоге `Tools/`
- Пересоберите проект (`dotnet build`)

### Отказ в разрешении

**Проблема**: выполнение инструмента завершилось ошибкой разрешения.

**Решение**:
- Проверьте аудитный журнал разрешений
- Убедитесь, что Кремниевое Существо имеет необходимые разрешения
- Проверьте настройки Глобального ACL
- Если это Куратор, проверьте, используется ли атрибут `[SiliconManagerOnly]`

### Инструмент возвращает ошибку при выполнении

**Проблема**: инструмент выполняется, но возвращает неудачный результат.

**Решение**:
- Проверьте сообщение об ошибке, возвращённое инструментом
- Убедитесь, что формат входных параметров корректен
- Просмотрите системные журналы для получения подробной информации об ошибке
- Протестируйте функциональность инструмента отдельно
