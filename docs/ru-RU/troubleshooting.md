## Часто задаваемые вопросы

### Сборка и компиляция

#### Проблема: сборка завершилась неудачей, отсутствуют зависимости

**Симптомы**:
```
error CS0246: The type or namespace name 'Microsoft.CodeAnalysis' could not be found
```

**Решение**:
```bash
dotnet restore
dotnet build
```

#### Проблема: .NET SDK не найден

**Симптомы**:
```
The .NET SDK could not be found
```

**Решение**:
1. Установите .NET 9 SDK: https://dotnet.microsoft.com/download/dotnet/9.0
2. Проверьте установку:
```bash
dotnet --version
```

### Проблемы подключения AI

#### Проблема: Ollama — отказ соединения

**Симптомы**:
```
Failed to connect to Ollama at http://localhost:11434
```

**Решение**:
```bash
# Проверьте, запущен ли Ollama
ollama list

# Запустите Ollama
ollama serve

# Проверьте соединение
curl http://localhost:11434/api/tags
```

#### Проблема: модель не найдена

**Симптомы**:
```
model "qwen2.5:7b" not found
```

**Решение**:
```bash
# Загрузите нужную модель
ollama pull qwen2.5:7b

# Список доступных моделей
ollama list
```

#### Проблема: Bailian — ошибка 404

**Симптомы**:
```
HTTP 404: Model not found
```

**Решение**:
1. Проверьте правильность API-ключа
2. Убедитесь, что имя модели совпадает с каталогом Bailian
3. Проверьте правильность регионального эндпоинта
4. Убедитесь, что аккаунт имеет доступ к модели

#### Проблема: Volcengine Ark — сбой подключения

**Симптомы**:
```
HTTP 401: Unauthorized
или
HTTP 404: Endpoint not found
```

**Решение**:
1. Проверьте правильность API-ключа
2. Убедитесь, что формат URL Endpoint корректен (по умолчанию: `https://ark.cn-beijing.volces.com/api/v3/chat/completions`)
3. Убедитесь, что параметр Model использует ID конечной точки вывода (например, `ep-20241212123456-abcde`), а не имя модели
4. Убедитесь, что аккаунт имеет доступ к конечной точке

#### Проблема: DeepSeek — ошибка аутентификации

**Симптомы**:
```
HTTP 401: Unauthorized
```

**Решение**:
1. Проверьте правильность API-ключа на [платформе DeepSeek](https://platform.deepseek.com/)
2. Убедитесь, что endpoint указан верно: `https://api.deepseek.com`
3. Проверьте, что на аккаунте есть достаточный баланс

#### Проблема: Zhipu AI / Ernie / Hunyuan — ошибка подключения

**Симптомы**:
```
HTTP 401: Unauthorized
или
Connection error
```

**Решение**:
1. Проверьте правильность API-ключа
2. Убедитесь, что endpoint указан верно:
   - Zhipu: `https://open.bigmodel.cn/api/paas/v4`
   - Ernie: `https://qianfan.baidubce.com/v2`
   - Hunyuan: `https://tokenhub.tencentmaas.com/v1` (TokenHub, рекомендуется) или `https://api.hunyuan.cloud.tencent.com/v1` (Legacy)
3. Проверьте, что аккаунт активирован и имеет доступ к выбранным моделям

#### Проблема: SiliconFlow — модель не найдена

**Симптомы**:
```
HTTP 404: Model not found
```

**Решение**:
1. Проверьте точное имя модели (включая префикс провайдера, например `deepseek-ai/DeepSeek-V3.2`)
2. Для профессиональных моделей используйте префикс `pro/`
3. Убедитесь, что модель доступна на вашем аккаунте SiliconFlow

### Проблемы времени выполнения

#### Проблема: порт уже занят

**Симптомы**:
```
HttpListenerException: Address already in use
```

**Решение**:

**Windows**:
```bash
netstat -ano | findstr :8080
taskkill /PID <PID> /F
```

**Linux/Mac**:
```bash
lsof -ti:8080 | xargs kill -9
```

**Или измените порт в конфигурации.**

#### Проблема: Кремниевое Существо не запускается

**Симптомы**:
- Статус существа отображается как «Error»
- В журналах отображается ошибка инициализации

**Решение**:
1. Проверьте, что Файл Души существует и корректен
2. Убедитесь, что AI-клиент настроен
3. Проверьте журналы для получения конкретной ошибки:
```bash
tail -f logs/*.log
```

#### Проблема: нехватка памяти

**Симптомы**:
```
OutOfMemoryException
```

**Решение**:
1. **SiliconLife.Default**: увеличьте размер кучи:
```bash
dotnet run --project src/SiliconLife.Default --server.gcHeapCount 4
```

2. **SiliconLife.Fast**: версия Fast сама по себе потребляет больше памяти (~500МБ), если память постоянно не хватает, рекомендуется:
   - Уменьшить количество параллельных Кремниевых Существ
   - Очистить старые данные для освобождения памяти

3. Очистка старых данных:
```bash
# Архивация старых журналов
mv logs/ logs-archive/
mkdir logs

# Очистка старой памяти
# Через Web UI: Управление памятью > Очистка
```

> **Подсказка**: SiliconLife.Default потребляет меньше памяти (~200МБ), подходит для сред с ограниченной памятью; SiliconLife.Fast потребляет больше памяти, но обеспечивает лучшую производительность, подходит для производственных сред.

### Проблемы разрешений

#### Проблема: отказ в разрешении

**Симптомы**:
```
Permission denied: FileAccess C:\Windows
```

**Решение**:
1. Проверьте текущие разрешения:
```bash
curl http://localhost:8080/api/permissions/list
```

2. Предоставьте разрешение:
```bash
curl -X POST http://localhost:8080/api/permissions/save \
  -H "Content-Type: application/json" \
  -d '{
    "permissionType": "FileAccess",
    "resourcePrefix": "C:\\Projects",
    "result": "Allowed",
    "description": "Allow project directory access"
  }'
```

3. Или используйте Web UI: Управление разрешениями

#### Проблема: разрешение не истекает

**Симптомы**:
- Разрешение остаётся действительным после времени истечения

**Решение**:
1. Проверьте синхронизацию системных часов
2. Убедитесь, что поле `expiresAt` установлено правильно
3. Очистите кэш разрешений

### Проблемы Web UI

#### Проблема: невозможно получить доступ к Web UI

**Симптомы**:
- Браузер отображает «Connection refused»

**Решение**:
1. Убедитесь, что сервер запущен
2. Проверьте правильный URL: `http://localhost:8080`
3. Проверьте настройки брандмауэра
4. Проверьте журналы на наличие ошибок запуска

#### Проблема: SSE не работает

**Симптомы**:
- Обновления в реальном времени не появляются
- Чат не передаётся потоком

**Решение**:
1. Проверьте, что браузер поддерживает SSE
2. Отключите прокси-буферизацию SSE
3. Проверьте стабильность сети
4. Попробуйте другой браузер

#### Проблема: UI выглядит сломанным

**Симптомы**:
- Стили некорректны
- Макет нарушен

**Решение**:
1. Очистите кэш браузера
2. Попробуйте другую тему: Настройки > Тема
3. Проверьте ошибки в консоли браузера
4. Отключите расширения браузера

### Проблемы хранения

#### Проблема: невозможно прочитать/записать данные

**Симптомы**:
```
IOException: Access denied
```

**Решение**:
1. Проверьте права доступа к файлам
2. Убедитесь, что путь хранения существует
3. Проверьте дисковое пространство
4. Запустите с соответствующими правами

#### Проблема: повреждение данных

**Симптомы**:
- Ошибки парсинга JSON
- Потеря данных

**Решение**:
1. Восстановите из резервной копии
2. Проверьте целостность хранилища:
```bash
# Через Web UI: Система > Проверка хранилища
```

3. Вручную восстановите повреждённые файлы

#### Проблема: повреждение файлов хранилища SpeedyPack (версия Fast)

**Симптомы**:
- Файл `.spk` не загружается
- Инициализация SpeedyStorage завершилась неудачей

**Решение**:
1. Используйте инструмент `SiliconLife.Speedy.Manager` для проверки и восстановления файлов `.spk`
2. Убедитесь, что индексный файл `.spk.idx` соответствует файлу `.spk`
3. Если индексный файл повреждён, удалите файл `.spk.idx`, система автоматически перестроит индекс
4. Восстановите файл `.spk` из резервной копии

#### Проблема: сбой автоматической компрессии SpeedyPack (версия Fast)

**Симптомы**:
- Файл `.spk` продолжает расти
- Нехватка дискового пространства

**Решение**:
1. Проверьте, что `SpeedyPackAutoCompactor` работает нормально
2. Вручную запустите операцию компрессии
3. Проверьте конфигурацию порога компрессии
4. Используйте инструмент `SiliconLife.Speedy.Manager` для ручной компрессии

### Проблемы плагинов

#### Проблема: сбой загрузки плагина

**Симптомы**:
```
Plugin load failed: Security check failed
```

**Решение**:
1. Проверьте, что плагин не ссылается на необъявляемые запрещённые пространства имён (например, `System.Runtime.InteropServices`, `System.Reflection.Emit`, `Microsoft.CodeAnalysis`)
2. Если плагину требуются `System.IO` или `System.Net.Http`, убедитесь, что плагин объявил возможности `FileIO` или `Network` через `[PluginCapability]`
3. Убедитесь, что плагин ссылается только на сборки из белого списка доверенных сборок
4. Проверьте, что плагин правильно реализует интерфейс `IPlugin`
5. Просмотрите журналы для получения подробной информации о причине сбоя проверки безопасности

#### Проблема: инструменты плагина не зарегистрированы

**Симптомы**:
- Плагин загружен успешно, но инструменты не появляются в списке

**Решение**:
1. Убедитесь, что класс инструмента в плагине правильно реализует интерфейс `ITool`
2. Проверьте, что класс инструмента является public
3. Убедитесь, что `ToolManager.ScanAllPluginAssemblies()` вызывается
4. Пересоберите плагин и перезапустите приложение

### Проблемы навыков

#### Проблема: навык не появляется в списке навыков или невидим для AI

**Симптомы**:
- Навык успешно сохранён на странице навыков в Web UI, но не отображается в списке / AI не вызывает навык

**Решение**:
1. Проверьте, что `id` и `description` навыка не пусты (черновики не предоставляются AI)
2. Навыки с неполными метаданными (`NeedsCompletion`) не внедряются в AI — дополните метаданные YAML front matter или позвольте AI дополнить их, затем сохраните снова
3. Проверьте, не отключён ли `{skillId}:execute` в матрице разрешений (отключённые навыки невидимы для AI)
4. Убедитесь, что глобальный переключатель `SkillEnabled` установлен в true
5. Горячая перезагрузка вступает в силу максимум через 30 секунд — обновите страницу или перезапустите приложение

#### Проблема: сбой выполнения навыка с подсказкой "not in whitelist"

**Симптомы**:
```
Tool 'xxx' is not available in skill 'yyy' (not in whitelist)
```

**Решение**:
- Добавьте инструмент в `tool_whitelist` навыка или очистите белый список, чтобы наследовать все инструменты существа

#### Проблема: достигнут лимит количества навыков

**Симптомы**:
```
Custom skill limit reached (50)
```

**Решение**:
1. Удалите неиспользуемые пользовательские навыки
2. Или увеличьте параметр конфигурации `MaxCustomSkillsPerBeing`

### Проблемы MCP

#### Проблема: сбой подключения MCP-сервера

**Симптомы**:
- Статус сервера показывает `error` или `disconnected`, `lastError` не пуст

**Решение**:
1. stdio-сервер: убедитесь, что `command` исполняем (например, `npx` в PATH), `arguments` корректны
2. http-сервер: проверьте доступность `endpoint` URL (брандмауэр, прокси)
3. Нажмите **Переподключить** на странице /mcp
4. Просмотрите подробности `lastError`, обычно: команда не существует, несовместимость версий, 404 эндпоинта

#### Проблема: инструменты MCP не внедряются в существо

**Симптомы**:
- Сервер подключён (`connected`), но AI не может вызвать инструмент `mcp_xxx_yyy`

**Решение**:
1. Убедитесь, что `enabled` сервера установлен в true
2. Убедитесь, что глобальный переключатель `McpEnabled` установлен в true
3. Проверьте матрицу разрешений: не отключён ли `mcp_{serverId}_{toolName}:execute`
4. В диалоге с существом используйте инструмент `mcp` (`list_tools`) для проверки фактически внедрённых имён инструментов

#### Проблема: добавление сервера возвращает ошибку формата ID

**Симптомы**:
```
Server id must contain only lowercase letters, digits and underscores
```

**Решение**:
- ID сервера допускает только строчные буквы, цифры и подчёркивания (например, `filesystem`, `github_tools`)

### Проблемы платформ мгновенных сообщений

#### Проблема: сообщения Feishu не приходят

**Решение**:
1. Проверьте адрес обратного вызова и порт в настройках подписки на события открытой платформы Feishu (`listenPort` + `callbackPath`)
2. Убедитесь, что `Encrypt Key` / `Verification Token` совпадают с конфигурацией
3. Для локальной разработки можно использовать мастер OAuth-авторизации (авторизация одним щелчком на странице конфигурации); для обратного вызова событий требуется публичная доступность или использование туннеля интрасети
4. Просмотрите ошибки проверки подписи/расшифровки в журнале

#### Проблема: тайм-аут OAuth-авторизации

**Симптомы**:
- Страница авторизации показывает статус `timeout`

**Решение**:
1. Срок действия сессии авторизации — 5 минут, после тайм-аута снова нажмите кнопку авторизации
2. Убедитесь, что адрес обратного вызова `/im/feishu/callback` доступен для Feishu (`redirectBaseUrl` настроен правильно)
3. Отображение статуса на фронтенде зависит от SSE; при разрыве SSE можно опрашивать `/im/{platform}/status` как запасной вариант

#### Проблема: `${ENV_VAR}` подстановочный знак не разрешается

**Симптомы**:
- Платформа мгновенных сообщений не подключается, значение конфигурации остаётся текстом подстановочного знака

**Решение**:
1. Убедитесь, что переменная окружения установлена до запуска процесса (перезапустите приложение для применения)
2. Проверьте написание имени переменной (поддерживается только `[A-Za-z_][A-Za-z0-9_]*`)
3. Примечание: сохранение подстановочного знака в config.json является проектным поведением — разрешение происходит в копии в памяти

#### Проблема: только одна платформа из нескольких IM получает сообщения

**Решение**:
- Исходящие сообщения транслируются на все включённые платформы; сбой отправки на одну платформу тихо изолируется — проверьте, не истёк ли токен этой платформы (повторная авторизация или обновление ключа)

### Проблемы рабочих заметок

#### Проблема: невозможно создать рабочую заметку

**Симптомы**:
```
Failed to create work note
```

**Решение**:
1. Проверьте, что Кремниевое Существо существует и находится в рабочем состоянии
2. Убедитесь, что путь хранения имеет права на запись
3. Проверьте, что содержимое не пустое (содержимое обязательно)
4. Просмотрите журналы для получения подробной информации об ошибке

#### Проблема: поиск заметок не даёт результатов

**Симптомы**:
- Поиск по ключевому слову возвращает пустые результаты
- Но вы уверены, что соответствующие заметки существуют

**Решение**:
1. Проверьте правильность написания ключевого слова
2. Попробуйте использовать более общее ключевое слово
3. Убедитесь, что заметка содержит это ключевое слово (с учётом регистра)
4. Увеличьте значение параметра `max_results`

#### Проблема: медленная генерация каталога заметок

**Симптомы**:
- Долгое время ответа при генерации каталога
- У существа много заметок (>1000 страниц)

**Решение**:
1. Это нормальное поведение, требуется обход всех заметок
2. Рассмотрите регулярную архивацию старых заметок
3. Используйте функцию поиска вместо просмотра каталога
4. Запланированная оптимизация: добавление механизма кэширования каталога

### Проблемы Сети Знаний

#### Проблема: запрос знаний возвращает пустые результаты

**Симптомы**:
```
No knowledge triples found
```

**Решение**:
1. Проверьте написание субъекта и предиката
2. Убедитесь, что знания добавлены в сеть
3. Используйте функцию поиска для нечёткого сопоставления:
```json
{
  "action": "search",
  "query": "ключевое слово"
}
```

#### Проблема: сбой поиска пути знаний

**Симптомы**:
```
No path found between concepts
```

**Решение**:
1. Убедитесь, что обе концепции существуют в Сети Знаний
2. Проверьте, существует ли связующий путь (возможно, нет прямого или косвенного отношения)
3. Попробуйте добавить больше знаний для установления связей
4. Снизьте ограничение длины пути (если установлено)

#### Проблема: сбой валидации знаний

**Симптомы**:
```
Knowledge validation failed
```

**Решение**:
1. Проверьте правильность формата триплета (субъект, предикат, объект обязательны)
2. Убедитесь, что достоверность находится в диапазоне 0.0-1.0
3. Проверьте наличие дублирующихся триплетов
4. Просмотрите подробности ошибки валидации для понимания конкретной проблемы

#### Проблема: неточная статистика Сети Знаний

**Симптомы**:
- Статистические данные не соответствуют ожиданиям
- Статистика не обновляется после добавления знаний

**Решение**:
1. Статистика может обновляться с задержкой в несколько секунд (кэширование)
2. Проверьте, успешно ли выполнились операции удаления
3. Перезапустите приложение для принудительного обновления статистики
4. Повторно запросите статистику через API

### Проблемы управления проектами

#### Проблема: невозможно создать проект

**Симптомы**:
```
Failed to create project
```

**Решение**:
1. Проверьте, что название проекта не пустое (обязательно)
2. Убедитесь, что название проекта уникально
3. Проверьте, что путь хранения имеет права на запись
4. Просмотрите журналы для получения подробной информации об ошибке

#### Проблема: потеря данных проекта

**Симптомы**:
- Информация о проекте не загружается
- Файлы проекта повреждены

**Решение**:
1. Проверьте, существует ли каталог хранения проекта
2. Восстановите данные проекта из резервной копии
3. Убедитесь, что формат JSON-файлов корректен
4. Вручную восстановите повреждённые файлы проекта

#### Проблема: сбой назначения проектной роли

**Симптомы**:
```
Failed to assign role
```

**Решение**:
1. Убедитесь, что Кремниевое Существо добавлено в проект
2. Проверьте, что имя роли корректно
3. Убедитесь, что инициатор является Кремниевым Куратором
4. Просмотрите журналы для получения подробной информации об ошибке

#### Проблема: рабочий процесс не запускается

**Симптомы**:
- Сбой создания экземпляра рабочего процесса
- Переходы состояний не выполняются

**Решение**:
1. Проверьте, что шаблон рабочего процесса определён
2. Убедитесь, что начальное состояние правильно установлено
3. Подтвердите, что проект привязан к шаблону рабочего процесса
4. Проверьте журналы рабочего процесса на наличие ошибок переходов

### Проблемы разрешений инструментов

#### Проблема: операция инструмента отклонена

**Симптомы**:
```
Tool operation denied: network:post
```

**Решение**:
1. Проверьте конфигурацию разрешений инструментов Кремниевого Существа:
```bash
curl http://localhost:8080/api/beings/tool-permissions?beingId=<id>
```

2. Обновите разрешения инструментов:
```bash
curl -X PUT http://localhost:8080/api/beings/tool-permissions \
  -H "Content-Type: application/json" \
  -d '{
    "beingId": "being-uuid",
    "permissions": {
      "network:post": "allowed"
    }
  }'
```

3. Или используйте Web UI: Существа → Разрешения инструментов

#### Проблема: разрешения инструментов проекта не работают

**Симптомы**:
- Разрешения инструментов на уровне проекта работают не так, как ожидалось

**Решение**:
1. Убедитесь, что разрешения на уровне проекта правильно настроены
2. Проверьте, нет ли конфликтов между разрешениями уровня Кремниевого Существа и уровня проекта
3. Разрешения уровня проекта независимы от уровня Кремниевого Существа, берётся пересечение обоих
4. Просмотрите аудитный журнал для подтверждения результатов проверки разрешений

## Проблемы производительности

### Медленное время отклика

**Оптимизация**:
1. Снизьте сложность AI-модели
2. Включите кэширование
3. Очистите старые данные
4. Увеличьте системные ресурсы

### Высокое использование CPU

**Проверьте**:
- Слишком много работающих Кремниевых Существ
- Бесконечные циклы в инструментах
- Частое выполнение таймеров

**Решение**:
- Уменьшите количество параллельных Кремниевых Существ
- Оптимизируйте код инструментов
- Настройте интервалы таймеров

### Высокое использование памяти

**Мониторинг**:
```bash
# Через Web UI: Панель управления > Память
```

**Оптимизация**:
- Очистите старую память
- Уменьшите размер контекста
- Реализуйте пагинацию
