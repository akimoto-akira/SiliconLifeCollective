# ForgeMindForUE 插件已知限制与信任边界

## exec_console 返回值不可信
### 问题
通过 `exec_console` 执行控制台命令（如 `getactor`、`setactor`）时，返回的 JSON 结果可能不完整或与实际状态不符。

### 原因
`exec_console` 是引擎底层接口，输出依赖命令实现者自行序列化，部分命令未正确实现输出或输出格式不规范。

### 解决方案
- 关键操作（如读取属性）应使用 ForgeMindForUE 提供的结构化 API（如 `get_actor_property`、`list_blueprint_variables`）
- 若必须用 `exec_console`，应二次验证：设置后立即读取确认

## 脏资产 vs 磁盘资产
### 概念澄清
- **脏资产（Dirty Asset）**：内存中已修改但未保存到磁盘的资产。编辑器关闭时会提示保存。
- **磁盘资产**：已保存到磁盘的 .uasset 文件。

### 影响
- ForgeMindForUE 的 `create_blueprint`、`add_blueprint_variable` 等操作会立即在内存中生效，资产标记为脏（dirty）
- 必须通过编辑器的保存流程（Save All 或关闭时的保存提示）才会写入磁盘
- 重启编辑器而不保存，所有脏修改会丢失

### 最佳实践
关键修改后主动执行 `Save All`，或提醒用户保存。

## 知识库边界规则
### 入库标准
应写入知识库的内容：
- 实战经验与踩坑教训（如 TMap 蓝图限制、Transform 格式）
- 引擎破坏性改动与版本差异
- 项目特定的架构约定与设计决策

不应写入知识库的内容：
- 类参考、API 文档（应查源码或官方文档）
- 引擎事实性知识（如函数签名、属性列表）

### 原因
知识库是经验沉淀，不是文档镜像。保持精简，避免冗余。
