# Демо Режима Загрузки путём Компиляции Исходного Кода CS

Плагин, загружаемый из исходных файлов `.cs` вместо предварительно скомпилированной DLL, демонстрирующий режим компиляции исходного кода CS в PluginLoader (введён в task-389).

## Как Работает Режим Исходного Кода CS

Когда PluginLoader сканирует каталог плагина и **не находит DLL**, он автоматически переходит в режим исходного кода CS:

```
1. PluginLoader сканирует каталог плагина → DLL не найдена
2. Переходит в режим исходного кода CS
3. cs.txt найден → построчное чтение, загружаются только указанные файлы .cs
   (Нет cs.txt → загружаются все файлы *.cs в каталоге)
4. Сканирование соседних DLL → доверенные DLL добавляются как ссылки напрямую;
   недоверенные DLL должны пройти ScanForbiddenReferences
5. CompilationCore (ограниченный режим) компилирует файлы .cs в DLL в памяти
6. Байты DLL в памяти записываются во временный файл для сканирования ScanForbiddenReferences
7. Сканирование пройдено → рефлексия находит реализацию IPlugin → создание экземпляра
8. Журнал показывает: "Plugin loaded [CS-Source]: {Id} v{Version} from {DirName}"
```

## cs.txt — Белый Список Выборочной Загрузки

Файл `cs.txt` указывает, какие файлы `.cs` компилировать, по одному имени файла на строку:

```
Plugin.cs
```

- **Указанные файлы**: Компилируются и загружаются (напр.: `Plugin.cs`)
- **Не указанные файлы**: Игнорируются компилятором (напр.: `Helpers.cs`)
- **Строки, начинающиеся с `#`**: Рассматриваются как комментарии
- **Пустые строки**: Игнорируются
- **Нет cs.txt**: Загружаются все файлы `*.cs` в каталоге

## Режим Исходного Кода CS vs Режим DLL

| Аспект | Режим DLL | Режим Исходного Кода CS |
|--------|-----------|------------------------|
| Формат плагина | Предварительно скомпилированная `.dll` | Исходные файлы `.cs` |
| Триггер загрузки | DLL найдена в каталоге плагина | DLL нет, файлы `.cs` присутствуют |
| Компиляция | Во время сборки | Во время загрузки PluginLoader'ом |
| Производительность | Нет накладных расходов на компиляцию | Накладные расходы компиляции Roslyn при запуске |
| Сканирование безопасности | Прямое сканирование метаданных PE | Компиляция → временная DLL → сканирование метаданных PE |
| Префикс журнала | `Plugin loaded:` | `Plugin loaded [CS-Source]:` |
| Лучше всего для | Продакшн-развёртывание | Итерация разработки |

## Обработка Ошибок

| Сценарий | Поведение |
|----------|-----------|
| Нет DLL, нет файлов .cs | Предупреждение: "No DLL and no CS source files found" |
| Ошибки компиляции | Ошибка: Подробные диагностические сообщения записаны в журнал |
| Сбой сканирования безопасности | Ошибка: Все нарушения перечислены, плагин отклонён |
| Запись cs.txt не найдена | Предупреждение: "cs.txt entry not found or not a .cs file" |
| Сбой сканирования соседней DLL | Предупреждение: DLL не добавлена как ссылка, компиляция продолжается |

## Примечание по Безопасности

Плагины в режиме исходного кода CS проходят **то же сканирование безопасности**, что и плагины в режиме DLL. Скомпилированная сборка записывается во временный DLL-файл и сканируется с помощью `ScanForbiddenReferences` — то же сканирование, которое проходят предварительно скомпилированные DLL. Все правила запрещённых пространств имён/типов/членов/строк применяются идентично.

Плагины по-прежнему загружаются в изолированном контексте и сканируются на запрещённые ссылки пространств имён (напр.: `System.IO`, `System.Net.Http`). См. [Документацию по Безопасности](../../docs/ru-RU/security.md) для подробностей.
