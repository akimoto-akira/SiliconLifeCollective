# Минимальная демонстрация плагина

Минимальная реализация `IPlugin`, демонстрирующая жизненный цикл плагина с жёстко заданными значениями.

## Обзор интерфейса IPlugin

Каждый плагин SiliconLife должен реализовать интерфейс `IPlugin`, определённый в `SiliconLife.Collective`：

```csharp
public interface IPlugin
{
    string Id { get; }
    string GetName(Language language);
    string Version { get; }
    string GetDescription(Language language);
    string GetAuthor(Language language);
    void OnLoad();
    void OnStart();
    void OnStop();
    void OnUnload();
}
```

### Сводка свойств

| Член | Тип | Описание |
|------|-----|----------|
| `Id` | `string` | Уникальный идентификатор, должен быть стабильным между версиями (напр. `"com.siliconlife.demo.minimal"`) |
| `GetName(Language)` | `string` | Читаемое отображаемое имя, локализованное через перечисление `Language` |
| `Version` | `string` | Строка семантической версии (напр. `"1.0.0"`) |
| `GetDescription(Language)` | `string` | Краткое описание функциональности плагина |
| `GetAuthor(Language)` | `string` | Имя автора или организации |

## Порядок вызова жизненного цикла

Хост вызывает методы жизненного цикла в строгом порядке：

```
OnLoad → OnStart → [Работает] → OnStop → OnUnload
```

| Метод | Когда вызывается | Типичное использование |
|-------|-----------------|----------------------|
| `OnLoad()` | Один раз при загрузке DLL плагина в хост | Проверка конфигурации, регистрация типов, подготовка ресурсов |
| `OnStart()` | Когда хост полностью запущен и все плагины загружены | Взаимодействие с другими плагинами, запуск фоновых задач |
| `OnStop()` | При корректном завершении работы хоста | Освобождение ресурсов, очистка буферов, сохранение состояния |
| `OnUnload()` | При выгрузке плагина из процесса хоста | Финальная очистка |

## Эта демонстрация

Этот плагин возвращает жёстко заданные значения для всех свойств и оставляет методы жизненного цикла пустыми. Это самая простая отправная точка для разработки плагинов.

## Примечание по безопасности

Плагины загружаются в изолированном `AssemblyLoadContext` и сканируются на запрещённые ссылки на пространства имён (напр. `System.IO`, `System.Net.Http`). Подробности см. в[документации по безопасности](../../docs/ru-RU/security.md).
