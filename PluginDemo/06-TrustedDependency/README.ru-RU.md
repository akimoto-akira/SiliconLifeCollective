# Демо доверенной зависимости

Демонстрирует использование `Newtonsoft.Json` — библиотеки, которая внутренне интенсивно использует рефлексию — в качестве доверенной сборки. Сканер безопасности PluginLoader полностью пропускает доверенные сборки, позволяя плагинам ссылаться на них без срабатывания нарушений.

## Механизм белого списка TrustedAssemblies

`PluginLoader` поддерживает статический белый список open-source библиотек, которые являются **доверенными по умолчанию**:

```csharp
private static readonly HashSet<string> TrustedAssemblies = new(StringComparer.Ordinal)
{
    // Сериализация
    "Google.Protobuf",
    "protobuf-net",
    "Newtonsoft.Json",        // ← Это демо использует эту библиотеку
    "MessagePack",
    "YamlDotNet",

    // Логирование
    "Serilog", "NLog",

    // Microsoft.Extensions.*
    "Microsoft.Extensions.Logging.Abstractions",
    "Microsoft.Extensions.DependencyInjection.Abstractions",
    // ...

    // Доступ к данным / маппинг
    "Dapper", "AutoMapper",

    // Валидация и диспетчеризация сообщений
    "FluentValidation", "MediatR",
};
```

### Критерии допуска

Библиотека может быть добавлена в `TrustedAssemblies`, если она соответствует **всем трём** критериям:

| # | Критерий | Обоснование |
|---|----------|-------------|
| 1 | Широко используемый open-source проект (MIT / Apache 2.0 / BSD) | Публично аудируемый код |
| 2 | Публично доступный исходный код | Общественный контроль гарантирует отсутствие вредоносного поведения |
| 3 | Поддерживаемый NuGet пакет от доверенного поставщика/сообщества | Целостность цепочки поставок |

### Основа идентификации

Сканер идентифицирует доверенные сборки по их `AssemblyDefinition.Name` в PE-метаданных — **а не по имени DLL файла**. Это предотвращает обход проверок путём переименования вредоносной DLL в `Newtonsoft.Json.dll`.

## CollectTrustedTypeRefs — Транзитивное освобождение

Когда PluginLoader загружает директорию плагина, он выполняет двухфазное сканирование:

```
Фаза 1: CollectTrustedTypeRefs(pluginDir)
├── Перечисление всех файлов *.dll в директории плагина
├── Для каждой DLL: чтение PE-метаданных → проверка AssemblyDefinition.Name
├── Если имя ∈ TrustedAssemblies:
│   └── Сбор ВСЕХ записей TypeReference → пары (namespace, typeName)
└── Возвращает: HashSet<(string Namespace, string Name)>

Фаза 2: ScanForbiddenReferences(pluginMainDll, trustedTypeRefs)
├── Слой 0:   Быстрый выход по белому списку (если основная DLL доверена → проход)
├── Слой 0.5: Транзитивное освобождение (пропуск TypeRef из набора trustedTypeRefs)
├── Слой 1:   Сканирование таблицы TypeRef
├── Слой 2:   Сканирование таблицы ExportedType
├── Слой 3:   Сканирование таблицы MemberRef (опасные методы)
├── Слой 4:   Маркеры небезопасного кода + P/Invoke
└── Слой 5:   Сканирование кучи строк #US
```

### Почему транзитивное освобождение важно

Newtonsoft.Json внутренне ссылается на типы вроде `System.Reflection.MemberInfo`, `System.IO.TextReader` и др. Когда ваш плагин ссылается на Newtonsoft.Json, компилятор может встроить эти транзитивные TypeRef в DLL **вашего** плагина. Без транзитивного освобождения ваш плагин был бы помечен за ссылку на `System.IO.TextReader` — даже если вы никогда не используете его напрямую.

`CollectTrustedTypeRefs` решает эту проблему, предварительно собирая все TypeRef из доверенных DLL и отмечая их как «известные безопасные» во время основного сканирования.

## Как добавить новую доверенную зависимость

Чтобы добавить новую библиотеку в белый список:

1. Убедитесь, что она соответствует трём вышеуказанным критериям допуска
2. Добавьте строку в HashSet `TrustedAssemblies` в `PluginLoader.cs`:
   ```csharp
   "YourLibraryName",  // Краткое описание почему она доверена
   ```
3. Поместите DLL библиотеки в директорию плагина (рядом с основной DLL плагина)
4. Сканер автоматически соберёт её TypeRef и освободит от проверки

> **⚠️ Важно:** Добавление библиотеки в `TrustedAssemblies` означает, что сканер **не** будет проверять её внутренний код. Добавляйте только библиотеки, которым вы полностью доверяете.

## Это демо

Этот плагин использует Newtonsoft.Json без каких-либо деклараций `PluginCapability`:

| Функция | Внутреннее поведение Newtonsoft.Json | Почему работает |
|---------|--------------------------------------|-----------------|
| `JsonConvert.SerializeObject` | Использует рефлексию для перечисления свойств | DLL Newtonsoft.Json проходит белый список слоя 0 |
| `JsonConvert.DeserializeObject<T>` | Вызывает `Activator.CreateInstance`, устанавливает свойства через рефлексию | Транзитивные TypeRef освобождены на слое 0.5 |
| Манипуляции с `JObject` / `JArray` | Использует `System.Linq.Expressions`, динамическую диспетчеризацию | Все внутренние ссылки собраны `CollectTrustedTypeRefs` |

### Ключевое отличие от PluginCapability

| Механизм | Область | Случай использования |
|----------|---------|---------------------|
| `TrustedAssemblies` | Освобождает целую **библиотеку** (и её транзитивные ссылки) от сканирования | Известные open-source зависимости |
| `PluginCapability` | Освобождает **код вашего плагина** от запретов определённых пространств имён | Плагину нужен прямой доступ к System.Net/IO/Process |

Плагин, использующий только доверенные зависимости, **не нуждается** в декларации `PluginCapability`. Сканер обрабатывает всё автоматически.

## Примечание по безопасности

Доверенные сборки освобождены от сканирования безопасности, поскольку являются аудируемыми open-source проектами. Однако **код вашего плагина** по-прежнему полностью сканируется. Если ваш плагин напрямую ссылается на `System.IO.File` или `System.Net.Http.HttpClient`, он всё равно будет заблокирован — если вы не объявите соответствующую `PluginCapability`. См. [документацию по безопасности](../../docs/ru-RU/security.md).
